### zone 职责

| zone | 职责（唯一） | 明确不做 |
|---|---|---|
| **Z0 页题** | 页面身份 + 副题一句话价值 + 两个数据面的统一刷新入口与数据时刻（「更新于 HH:MM:SS」） | 不放任何筛选或统计内容 |
| **Z1 统计画像** | 近 14 天**固定窗口**的命中画像：4 指标、日趋势、方式占比、来源分布、关键词榜；产出「修剪关键词」决策（零命中词 → 深链设置） | 不随列表筛选变化（口径解耦是设计意图，必须显性标注）；不做日期/来源过滤统计（getStats 仅支持天数窗口，ipc.ts:135-138） |
| **Z2 命中记录** | 查询视图：筛选（窗口/来源/方式/文本）→ 服务端分页列表 → 行内动作（打开原帖、反馈投票） | 不做实时订阅（手动刷新）；不放统计聚合 |

**两窗口口径规则（audit #4 的解法，全页最高优先级文案）**：
1. Z1 卡头 aux 恒显：`近 14 天固定窗口 · 不随下方筛选变化`；aux 的 title 全文：`统计是长期画像（帮你修剪关键词、看来源结构），列表是查询视图；两者口径独立，数字不同属正常`。
2. Z2 卡头 aux 恒显当前窗口：`窗口 09-13 ～ 09-19 · 7 天 · 共 3,102 条`。
3. 列表筛选变化时 Z1 数字纹丝不动——两处标注让用户在任何时刻都能对照出「哪个数字属于哪个窗口」。

## 4. 关键交互与键盘

### 4.1 键盘表（ia 原则 6 / dsn §6「键盘优先」）

| 键 | 行为 | 作用域 |
|---|---|---|
| `Cmd/Ctrl+3` | 切到历史命中（全局五分区快捷键之一，ia §1.4） | 全局 |
| `/` | 聚焦搜索框 | 本页激活且焦点不在输入框时 |
| `Esc` | 搜索框内：有文字先清空，已空则失焦还焦给列表 | 搜索框 |
| `PageUp` / `PageDown` | 上一页 / 下一页（等效点按分页按钮，禁用边界同样生效） | 焦点不在 input/select 内 |
| `↑` / `↓` | 列表容器（tabindex=0，roving）行间移动焦点行，`.hit-focus` 描边 | 列表容器持有焦点时 |
| `Enter` | 打开焦点行原帖（走主进程白名单受控跳转，pc §6.8） | 焦点行存在时 |
| `Enter`（页码框） | 跳转到输入页码（钳到 [1, 总页数]） | 页码输入框 |
| `Tab` | 自然顺序：日期 chips → 来源 → 方式 → 搜索 → 重置 → 列表容器 → 行内标题/投票 → 分页栏 | 全页 |

可达性：chips 补 `aria-pressed`（audit §5.4 缺口）；页码输入 `aria-label="跳转到指定页"`；错误条 `role="alert"`（ia §5.4）。

### 4.2 交互细则

1. **搜索防抖 300ms + 序号守卫**：现状机制保留（History.tsx:77-84、363-365），行为不变。
2. **筛选变化自动回第一页**；筛选收窄致页码越界自动收口到最后一页（现状 History.tsx:401-409 保留）。
3. **切页大小保持数据位置**：从 50 切 100/200 时，新页码 = `floor(当前页 × 旧档 / 新档)`，不回第一页；切档后焦点留在分页栏。
4. **零命中深链**：点 `去调整关键词` → 切设置页 → 锚点滚动到「监控内容 → 关键词」卡并 800ms 高亮（ia 流 4 走查项）。
5. **筛选状态保持**：切分区再返回，筛选、页码、滚动位置原样（ia §5.1 state-preservation；实现注记：App 层缓存本页状态或 keep-alive，本稿只定行为）。
6. **统计折叠状态**记忆到本地（localStorage 键 `fw.history.statsCollapsed`），下次进入沿用。
7. **标题点击**打开原帖：主进程白名单受控跳转 + 失败 title 提示（现状 openExternalWithTitleHint 机制保留）。
8. **投票**：三态（记票 / 同向撤销 / 反向改票），乐观更新、失败回滚，本地高亮会话级（HitList.tsx:129-136 语义原样迁入共用组件；历史页行为与监控台一致，修 audit §4.1-4「两页行结构不一致」）。
9. **sparkbar 柱 hover**：加深 10% + title；点击柱 = 把列表窗口设为该单日（from=to=该日），日期 chips 落到 `自定义`——把「趋势上看到峰值 → 想看那天具体是什么」变成一跳。

## 5. 状态设计

### 5.1 空态（三态区分，检索 A-1 采用：无结果必须带建议动作，禁死胡同）

| 态 | 判定 | 标题 / hint / 动作 |
|---|---|---|
| **默认窗口空** | 默认筛选（近 7 天 · 全部来源 · 无方式 · 无搜索）且 total=0 | 题 `近 7 天没有命中记录`；hint `命中由监控运行时自动落盘，重启不会丢。若刚改过关键词或兴趣描述，等下一轮轮询后再来看。`；动作 ① `扩大到近 30 天`（一键改窗口）② `去配置关键词`（深链设置①） |
| **筛选后空** | 非默认筛选且 total=0 | 题 `当前筛选条件下没有命中`；hint `换个日期范围、来源或命中方式试试；也可以直接搜标题或命中词。`；动作 `重置筛选` |
| **本页为空**（兜底） | total>0 但 items 空（越界收口竞态兜底） | 题 `本页没有记录`；hint `筛选收窄后页码已自动收口，回到第一页看看。`；动作 `回到第一页` |

统计窗口空（stats.total=0 且非错误）：指标格显 `0 / — / 0 天 / 0`，sparkbar 全空槽，展开区显示灰字 `近 14 天没有任何命中记录。命中在监控运行且关键词 / 兴趣 / 规则匹配时产生。`——不用 EmptyState 大组件（统计区无行动需求，避免误占高度）。

### 5.2 加载态（ia §5.1：保留旧数据 + 局部 busy，禁整屏替换——修 audit #5）

| 场景 | 表现 |
|---|---|
| 首载（无旧数据） | 列表区居中 `正在读取历史记录…`；统计区 `正在读取统计…`（仅此场景允许文字型占位，本地 IPC 快速返回） |
| 非首载查询（筛选/翻页/防抖/刷新） | **旧列表原样保留**，列表区 `opacity .55`，卡头 aux 尾追加 `查询中…`（>1s 才出现）；筛选控件**不禁用**（允许连续输入，序号守卫防覆盖） |
| 刷新按钮 | 图标旋转 + disabled，文字不变 |
| 页面隐藏到托盘 | 不做任何定时刷新（现状即无订阅；dsn §2 telemetry 规则③） |

### 5.3 错误态（ia §5.4「错误 ≠ 空」，修 audit §5.2 表中 History 两个违规面）

| 数据面 | 表现 |
|---|---|
| 列表 queryHits | 筛选行下、列表上方错误条：`命中记录读取失败：{原因}` + `重试`；**旧结果保留**（列表不再降 opacity，恢复正常交互）；首次即失败且无旧数据时列表区显示 EmptyState 变体：题 `读取失败`、hint={原因}、动作 `重试`。`role="alert"` |
| 统计 getStats | 沿用现状范本（History.tsx:463-480）：错误条 + 重试 + 旧数据保留，文案见 §3.2 |
| 来源下拉 getConfig | 不再静默（audit §5.2 最后一行）：下拉保留统计来源兜底，尾部加不可选项 `（来源清单读取失败，仅显示历史出现过的来源）`，下拉失焦后 5s 内重试一次；连续失败保持提示不升级打扰 |

**已知限制（如实）**：主进程 queryHits「查询面不抛；readDay 单日失败按空处理」（src/main/desktop/ipc.ts:293-297），getStats「读取失败按空数据聚合（不抛）」（ipc.ts:301-310）——单日文件损坏时该日数据**静默缺失**，渲染层错误条只能覆盖 IPC 通道本身失败。界面无法标注此事，排障依赖主进程日志；此为主进程行为，非本稿可解，记录在案。

### 5.4 大数据量（数千条命中）

1. **服务端分页为主**：50 / 100 / 200 三档（200 为 IPC 单次钳位上限，ipc.ts:258 / pc §6.4）+ 页码跳转 + 总页数，ia §5.1 定稿；**不引入虚拟化**（命中行高不定：语义命中带理由、规则命中带规则名；分页已钉死单次渲染 ≤200，ia §5.1 已论证）。
2. 3,000 条（60+ 页）走查：页码框输 `63` 直达末页；切 `每页 200 条` 后变 15 页；总数 `共 3,102 条` 千分位常显。`全部` 日期档 + 全库上万条同样被分页钳制，单次渲染恒 ≤200 行。
3. 行 `key` 沿用 `${sourceId}:${topicId}`（稳定）；行组件共用（§6），React 19 下 200 行可接受（audit §5.6 口径）。
4. 日期快捷 chips 让「先收窄再翻页」成为默认动线；sparkbar 柱点击直达单日（§4.2-9）。

## 7. 与 ia-interaction 的关系

**无推翻性决定，无需「与 IA 不同」单列。** 逐项核对：分区职责（§3 表）、固定 14 天统计口径、50/100/200 + 页码跳转、放弃虚拟化、加载态保留旧数据、错误≠空、state-preservation、零命中深链、命中行全应用单源——全部按 ia §3/§4 流 4/§5.1/§5.4 执行。

三项**细化**（IA 未规定、本稿补表现层，均不越分区边界）：

1. **统计明细默认折叠**（来源分布 + 关键词榜收进展开区）：IA 只说统计面板标注固定窗口，未规定披露层级。折叠依据 audit §5.6「统计常驻占满首屏、查询是主任务」；可发现性由常显概要行 `零命中关键词 M 个 → 去调整关键词` 保底——流 4 的行动入口不因折叠而隐藏。
2. **投票/锐评 emoji → SVG**：ia §3 写「含 👍/👎」指功能而非字形；dsn 红线「禁 emoji 图标」+ audit §5.4「投票无 aria-label」要求 SVG 化。功能与三态语义不变。
3. **日期快捷 chips**（今天/近7/近14/近30/全部/自定义）：IA 未规定窗口选择形态（现状是两个裸 date input）；chips 是「先收窄再翻页」动线（§5.4-4）的载体，`自定义` 档保留原 date input 能力，无功能损失。
