`已显示 150 / 1,240 条` + 按钮 `继续加载 +150`。加载后按钮消失、计数更新，无确认、无 toast。

### 2.8 确认语声明（诚实覆盖）

**本页不设确认对话框**：无删除、无写入、无破坏性操作，一切筛选与展开即时可逆——符合 ia §5.2 分层（只有「立即不可逆」才弹确认）。与确认最接近的两处交互按此处理：

## 3. 状态设计

### 3.1 空
见 §2.4 三态。历史日与实时环分别定义，杜绝「错误被算成空」。

### 3.2 加载
两条规则，来源 ia §5.1（「保留旧数据 + 局部 busy，禁止整屏替换」）：

| 场景 | 表现 |
|---|---|
| 首次进入，无任何旧数据 | Zone D 居中文字型加载 `正在读取判定记录…`（12px muted + 旋转 IconRefresh）。不做骨架——本地 IPC 快返回，>1s 才考虑骨架（ia §5.1 引 progressive-loading） |
| **同一数据面**内的刷新（10s 自刷 / 手动刷新 / 筛选变化 / 搜索防抖） | 列表原地保留，Zone A 的 `数据截至` 时间戳跳变 + 刷新按钮图标旋转（按钮文字不替换）。**不出现整屏 loading**——直接修掉现状 Dispositions.tsx:192-193 每次 load 都 `loading→true` 替换列表的行为 |
| **切换数据面**（实时↔某日、日↔日） | 显示文字型加载态。旧日的数据不能留着展示——那会与新选日期矛盾，比闪一下 loading 更误导 |

### 3.3 错误
见 §2.5。结构：红 tone 弱底条 + 原因 + `重试` + 旧数据保留（有旧数据时列表照常可读可滚）。错误期间 10s 自刷继续尝试，成功则错误条自动消失（恢复也是自愈的一部分）。

### 3.4 大数据量（单日上千条）
实时环恒 200 条（pc §6.4），无需处理；**历史日数据面是全量返回**（`dispositionsDay` 一次性返回该日 JSONL，ipc.ts:126-127），单日可达上千条。处理方案（详见 §6 差异节）：

- 首屏渲染最近 150 条（窗口 700px 高 × 行高约 32px ≈ 可视 16 行，150 行余量充足且 DOM 量小）；
- 滚至列表底部见 Zone E sticky 条，点 `继续加载 +150` 追加，直到该日全部；
- **不虚拟化**（ia §5.1 明确否掉全应用虚拟列表）、**不做触底自动加载**（滚动阅读中自动追加内容违反活列表规则的「阅读优先」精神）；
- 筛选/搜索在**全量已加载数据**上计算（不只是已渲染部分），计数显示 `筛选 87 / 1,240`——先有筛选后有加载时，命中的未渲染条目仍需「继续加载」到达，计数条不误导。

### 3.5 stale（自刷暂停期）
自刷暂停的三种触发（ia §5.1）与恢复策略：

| 触发 | 暂停语义 | 恢复 |
|---|---|---|
| 鼠标悬停列表区 | 临时暂停（防阅读重排） | 移开 2 秒后自动恢复 |
| 筛选激活（分组非「全部」/ 来源非「全部」/ 搜索非空） | 暂停自刷，新数据走「N 条新」角标 | 清空筛选后自动恢复 |
| 手动点 `暂停自刷` | 显式暂停，常驻 `数据截至` 标注 | 仅手动点 `自刷已暂停 · 恢复` |

暂停期间新到的记录**一律进角标不插列表**（活列表规则，ia §5.1；现状是全量替换 + reverse 重排，Dispositions.tsx:87-88，audit 问题 #11）。窗口隐藏到托盘时 UI 层自刷与动画整体停止，恢复显示立即刷一次（dsn §2 规则③、§6 挂机降负——现状 Dispositions.tsx:101-108 的定时器不感知窗口可见性，属实现层修复点，本设计只定行为）。

## 4. 关键交互与键盘

### 4.1 核心动线：排障搜索（pc §4.2 / ia 流 3）
打开去向（`Cmd/Ctrl+2`）→ 按 `/` 聚焦搜索 → 输入标题片段（300ms 防抖）→ 列表收窄到该帖的全部去向记录（轨迹自然呈现）→ 点击/Enter 展开看原因 → 按展开态的 `去…` 链接直达设置锚点。全程键盘可达，无一步依赖 hover。

### 4.2 行交互
- 单击行：展开/收起（同一时刻允许多行展开；展开是只读行为，无互斥必要）。
- `复制标题`：写剪贴板，按钮文字 `复制标题` → `已复制`（1.5s 后还原）。
- `去…` 跳转：走设置页锚点深链（ia §2.2 锚点支持带目标定位）；设置 dirty 时被全局 leavebar 拦截（§2.8）。
- 轨迹点击：点击轨迹中某条记录跳转（滚动+高亮 300ms）到对应行——同帖因果链可以反向追。

### 4.3 键盘表

| 键 | 行为 | 生效条件 |
|---|---|---|
| `Cmd/Ctrl+2` | 切到去向页（全局，ia §1.4；本页为消费方） | 任意 |
| `/` | 聚焦搜索框 | 焦点不在输入框时 |
| `j` / `↓`，`k` / `↑` | 列表行间移动焦点（roving tabindex；分组日期分隔条跳过） | 焦点在列表或页面空白 |
| `Enter` / `Space` | 展开/收起焦点行 | 焦点在行 |
| `Esc` | 逐级退：清空搜索 → 收起展开行 → 焦点回列表首行 | 焦点在输入框/展开行/列表 |
| `r` | 手动刷新 | 焦点不在输入框 |
| `p` | 暂停/恢复自刷 | 焦点不在输入框 |
| `1`…`5` | 切换五个 outcome 分组（与带修饰键的 `Cmd+1..5` 全局切页不冲突） | 焦点不在输入框 |
| `Tab` / `Shift+Tab` | 工具条、chips、行、展开区按钮间顺序移动 | 任意 |

所有可交互元素焦点环常显：浅色 `#15803D`、暗色 `#22C55E`（dsn §5 实测达标值），150-200ms 过渡。

### 4.4 可达性绑定（ia §5.5 落到本页）
- 分组 chips 补 `aria-pressed`（修 audit 问题 #10 现状缺失，Dispositions.tsx:145-155）；
- 行为 button 语义，`aria-expanded` 标展开态；
- 搜索框 `aria-label`；「N 条新」`role="status" aria-atomic="true"`（§2.6）；
- 图标全 SVG + `aria-hidden`，文本标签兜底（现状 icons.tsx 惯例保留）；
- 展开的完整 detail 即截断值的键盘可达披露（检索 B-2 结果 3）。

## 6. 与 IA 不同的决定（单列；均非推翻，两处缝隙补位 + 一处细化）

1. **IA §5.1 未覆盖「去向历史日」数据面，本设计补位**。ia 声称「所有大数据面都已被分页或 200 条环约束」，但其表格只列了「去向实时环（200 条内存）」；`dispositionsDay` 是一次性全量返回（ipc.ts:126-127），单日上千条不受该约束保护。补位方案：前端分段渲染（§3.4），**遵守** ia「不引入虚拟列表」「钉死单次渲染量」的精神，只是把「服务端分页」换成「客户端分段」——因为该 IPC 无分页参数，而本次交付不动 `src/**`。远期建议（P2，需主进程改造）：`dispositionsDay` 支持分段返回，届时去掉 Zone E。
2. **IA §5.1「恢复手动」细化为三种恢复策略**（§3.5 表）。ia 字面规定自动刷新「恢复手动」；若悬停/筛选触发的暂停也只靠手动恢复，用户会在无感知中长期停留在 stale 数据（`数据截至` 标注能兜底但不如不制造 stale）。细化后：自动触发的暂停自动恢复（移开/清筛选），显式暂停才要求显式恢复；暂停期间信息不丢（角标承接）。与 ia 原则 5「活列表阅读优先于新鲜度」一致，不构成对分区或交互骨架的推翻。
3. **无其他不认可项**。分区命名（去向/处置去向）、侧栏第 2 位、职责边界（不放统计/规则编辑）、错误一等公民、行内反馈不建 toast、EmptyState 三态、卡头 aux 徽标、来源名单源、chips aria-pressed、`Cmd+2`、锚点深链——全部直接遵守。
