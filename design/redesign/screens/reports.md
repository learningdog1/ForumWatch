### 2.5 确认语（唯一一处：重新生成）

按 IA §5.2 三层模型，「重新生成」属**立即不可逆**层（覆盖旧文件、且旧内容无撤销通道）→ 必须确认。形式取**行内确认条**而非模态对话框：单窗口桌面工具、上下文就在卡头下方，模态框过度打断（IA §5.4 行内反馈优先的同理）。确认条替换 B1 行 2 显示：

```
┌────────────────────────────────────────────────────────────┐
│ 重新生成会覆盖当前日报，并按配置再推送一次。确定？             │
│ [确认重新生成]（danger 描边）  [取消]（次级）     Esc 取消    │
└────────────────────────────────────────────────────────────┘
```

- 主操作 danger 描边样式（IA §5.2 引 quick-reference `destructive-emphasis`：danger 与 primary 视觉分离）。
- `Esc` 或点击确认条外任意处 = 取消。
- 「复制全文」「查看该日命中」「跳到日期」均**不**需要确认（无破坏性）；「展开更早」不需要（纯展开）。

### 3.2 生成事件与阅读优先（IA 原则 5 在本页的应用）

现状 `onDailyReport` 回调：选中日期 === 事件日期时直接 `setReport` 覆盖正文（Reports.tsx:126-129）。问题：用户正读「今天」的旧版日报、恰好手动/定时重生成完成时，正文在阅读中途被整篇替换、滚动位置失效。改造为**文档版活列表规则**（IA §5.1 活列表规则的阅读面推广）：

- 事件日期 ≠ 选中日期 → 只更新日期栏（现状行为，保留）；
- 事件日期 === 选中日期 且 当前正文区处于空态/生成反馈态 → 直接载入（现状行为，保留）；
- 事件日期 === 选中日期 且 用户已滚动离开顶部（scrollTop > 40px）→ **不替换正文**，卡头下方出现一次性角标条：`已生成新版本 · 点击查看`，点击或回滚到顶部才载入并保持锚点标题不变。角标 300ms 淡入（motion 2/10，一次性微交互，无循环动画，dsn §6）。

### 3.3 空态组合小概率但需定义

| 组合 | 呈现 |
|---|---|
| 日期列表错误 + 正文正常 | 日期栏只剩「今天」+ 错误行；正文不受影响（两数据面独立） |
| 日期列表空（从未生成过任何日报） | 日期栏只有「今天（未生成）」；无「更早」分组（现状 `historyDates.length > 0` 条件保留，Reports.tsx:165） |
| 「今天」在 dates 里但用户看的是历史 | 正常；「今天」行无 `未生成` sub（现状 Reports.tsx:163 条件保留） |

### 3.4 大数据量（上千条命中 → 模板模式上千行正文）

数据事实：LLM 模式受 `REPORT_MAX_TOKENS = 1500`（daily-report.ts:41）约束，正文有限；**模板模式逐条全列无上限**（daily-report.ts:282-302），上千条命中即上千行 markdown。策略（与 IA §5.1「全应用不引入虚拟列表」一致——但那是列表；长文档用文档手段）：

1. **分块 + `content-visibility: auto`**：渲染器按块级元素（h2 / h3 / ul / p）产出 React 节点，每个块级容器加 `content-visibility: auto; contain-intrinsic-size: auto 32px;`（ul 用 `auto 400px` 估值）。屏外块跳过布局与绘制，千行文档滚动帧率与百行无异；无按钮、无分页、无「加载更多」——阅读面不该有翻页交互。`prefers-reduced-motion` 无关（无动画）；窗口隐藏到托盘时本页无定时器，天然停刷（dsn §2 telemetry 规则③）。
2. **分组导航 chips**（B3 顶部，粘性）：块数 > 24 时显示，取全部 `##` 标题做 chips（模板模式即来源分组，daily-report.ts:283-286；LLM 模式如有 ## 同样适用），横向滚动一行，fs-12。点击 chip → `scrollIntoView({ behavior: 'smooth' })` 平滑定位（300ms 缓出，dsn §2 保留的参数精神）。块数 ≤ 24 时不显示（渐进披露：短文不需要目录）。
3. **截断检测**（LLM 模式专属）：尾块不含「数据说明」关键词（自家 prompt 要求结尾数据说明，daily-report.ts:203-207；自家两套模板都有尾注，daily-report.ts:269/303）→ 判定可能被 max_tokens 截断，正文末尾附 fs-12 灰提示：`这篇日报可能不完整（命中较多时 AI 摘要可能被截断）。可重新生成，或查看该日命中明细 →`（「查看该日命中明细」为同页跳转链接）。可解释性卖点的直接兑现（IA 原则 2）。
4. **模板行结构化渲染**：匹配 `- HH:MM [分类] 标题（命中方式）` 模式的列表行（daily-report.ts:301 固定格式）渲染为：时间 `HH:MM`（mono + tnum，dsn §3）+ 分类小 chip（复用 `.cat` 实底徽标族，global.css 徽标两族约定）+ 标题（前景色）+ 命中方式（fs-12 灰）。不匹配该模式的行（LLM 自由输出）回退普通列表行。上千行时这是扫读效率的主来源。

## 5. markdown 渲染方案（IA §6 未决项 1 的解）

### 5.1 决定：自写最小行内解析器，不引 markdown 库

理由：
1. 语法面窄且**来源可控**——日报只出自自家两条路径：LLM（prompt 明确要求 markdown，结构固定为「一段总述 + 要点列表 + 结尾数据说明」，daily-report.ts:203-207）与自家模板（daily-report.ts:263-305）。需要支持的行内语法只有四种：`**粗体**`、`` `代码` ``、`[文字](url)`、标题/列表块级规则（后者现状已实现，Reports.tsx:29-88）。
2. 项目零组件库纪律（audit §1）；为一个页面引 react-markdown + remark-gfm（依赖树六七十个包）不成比例。
3. GFM 表格在自家 prompt 中未被要求，LLM 输出概率低；未识别语法（表格管道符等）按普通段落原文渲染——**宽松解析，永不吞内容**，最坏情况回到现状（原文可见）。

### 5.2 行内语法规则（渲染器实现规格）

| 语法 | 渲染 | 不匹配时 |
|---|---|---|
| `**text**` | `<strong>`（同色加重） | 单个 `*` 原样 |
| `` `text` `` | `<code class="doc-code">`，mono 字体栈 + 弱底色（chip-bg） | 单个反引号原样 |
| `[text](url)` | `<a>`：accent 色 + 下划线；`title` = 完整 url；url 仅 http/https（其他协议不渲染为链接，原文显示）；点击走 `openExternal`（白名单在主进程侧裁决） | 括号不完整原样 |
| 其余行内文本 | React 文本节点（自动转义） | — |

安全红线：**全程 React 元素构造，禁 `dangerouslySetInnerHTML`**——文本节点自动转义，无 XSS 面；链接协议白名单在渲染层、域名白名单在主进程双层。

### 5.3 块级规则（现状 renderDoc 的三处改造）

1. **首个 h1 上提**：若首块是 `# ` 开头且包含「监控日报」（自家两套模板的固定头，daily-report.ts:265/276），该块**不在正文渲染**（信息已由 B1 卡头承载——消除「卡头今天 · 09-20 + 正文 # ForumWatch 监控日报 · 2026-09-20」双标题重复，audit §3 页面标题层级问题的对症处理）。不满足该条件的首块 h1 照常渲染（LLM 偶发自拟标题时不丢）。
2. **尾注弱化**：以「—— 数据说明」开头的行渲染为 fs-12 灰色、上边框分隔的尾注块（不再与正文同权重）。
3. **模板行结构化**：见 §3.4 第 4 条。

### 5.4 元信息解析规则（B1 行 2 / aux 胶囊的数据来源）

全部从 markdown 文本解析（`DailyReportInfo` 只有 date + markdown 两个字段，types.ts:530-535，无元数据可用——以下均为尽力解析，解析不到就不显示，遵循现状注释的降级哲学 Reports.tsx:6-7）：

| 元信息 | 规则 | 呈现 |
|---|---|---|
| 命中数 aux | 头 10 行匹配 `共\s*(\d+)\s*条` 或含「今日无命中」（现状 parseHitsSummary，Reports.tsx:21-27，保留） | B1 行 1 右侧胶囊：`共 12 条命中`（chip 样式）/ `今日无命中`（灰胶囊） |
| 生成模式 | 尾注含「模板模式」→ 模板；否则若存在「数据说明」（AI 口径）→ AI | B1 行 2：`AI 总结` / `模板模式（AI 生成失败时的降级）` |
| 完整性 | §3.4 第 3 条截断检测 | 追加 ` · 可能不完整`（点击滚到文末提示行） |
| 都解析不到 | — | B1 行 2 显示静态副题（§2.1） |

## 8. 与 IA 不同的决定

**无。** 分区归属（§3 表）、命名（「日报」）、副题文案、去 14 天截断、错误一等公民、行内反馈不建 toast、Cmd+4、活列表阅读优先，全部按 IA 执行。两处属**细化而非偏离**，列出备查：
