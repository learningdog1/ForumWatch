## 界面导览

应用为左右双栏结构：

- **左侧栏**：品牌、五个页签（📊 监控台 / 📅 今日回顾 / 📜 历史命中 / 🔍 流水 / ⚙️ 设置，图标 + 文字）、底部迷你运行状态（与托盘 tooltip 同口径）。设置页有未保存修改时，页签上会出现未保存圆点；此时切走页签会先弹提示条（放弃修改并切换 / 留在设置）。
- **监控台**（Dashboard）：
  - **状态卡**：运行状态徽标（运行中 / 已暂停 / Cloudflare 拦截 / 退避重试中）+ 四格指标（上次轮询、下次轮询、连续失败、累计命中）+ 最近错误。已暂停时"下次轮询"显示 `—`（不再排程）。状态卡下方有**挂起待推送**行（`⏳ 挂起待推送 N 条`，仅 N>0 时显示）——免打扰时段内或摘要模式下挂起的命中条数（语义见[推送细节](#推送细节)与[状态模型](#状态模型)）。
  - **来源状态块**：每个已启用来源一行——健康点、来源名、健康文案（退避中显示 mm:ss 倒计时）、最近成功时间。来源类型有 NodeSeek / V2EX / RSS 三种（RSS 来源显示 label 或 feed 域名）。
  - **AI 状态块**：生效模式徽标（字面 / 语义 / 字面+语义）、今日调用 `N` 与其中锐评 `N` 两行计数（**纯计数，无每日上限**；锐评一次调用计入两者）、降级提示（AI 未配置）、最近 AI 错误（评估成功后自动清空）。
  - **操作行**：⏸ 暂停监控 / ▶ 恢复监控（同一按钮随状态切换）、🔄 立即轮询（暂停状态下禁用）、✈ 发送测试通知（**向全部就绪通道广播**，不走路由）。
  - **最近命中**：最近 200 条命中记录（进程内存环形，重启后清空；`totalHits` 计数才跨重启累计，全天命中另落盘 `hits/`）。每条带来源徽标与命中方式徽标（**字面** / **语义** / **规则**），语义命中会显示 AI 的一句话判定理由，规则命中会显示命中的规则名（旧版本记录里的规则命中可能没有规则名——早期 jsonl 行缺该字段）。行尾有 👍/👎 反馈按钮（AI 反馈闭环，语义见[下文](#反馈闭环)）。
  - **运行日志**：最近 500 条日志（info/warn/error 三级，同样为内存环形）。
- **今日回顾**（Reports）：AI 日报页。左侧日期栏列出有日报的日期（新→旧，取最近 14 个），点击切换查看；顶部显示当天命中数摘要。今天还没有日报时空态提供「立即生成」按钮（详见[下文](#ai-语义监控与每日总结)）。
- **历史命中**（History）：`hits/*.jsonl` 落盘命中的跨日浏览器 + 统计面板（顶部统计 + 下方列表两个卡片）。
  - **统计面板**：近 14 天（固定窗口，与下方列表筛选无关——列表是查询视图、统计是画像；主进程接口支持 1-90 天，界面当前固定 14）命中的纯读聚合——四个指标块（总命中 / 推送失败率 / 命中日 / 来源数）、三命中方式占比（字面 / 语义 / 规则，堆叠比例条 + 图例）、来源分布 Top、关键词命中榜。**推送失败率**口径 = `notifyError` 非空的占比（静音不算失败）。**关键词命中榜**按命中次数降序；当前配置的包含词中统计窗口内从未命中的（大小写不敏感比对）灰字附尾标注"未命中，考虑移除"——是提示不是自动清理，改关键词去「设置 → 关键词」。
  - **历史命中列表**：日期范围（默认近 7 天，含两端）+ 来源下拉（配置来源 ∪ 统计中出现过的来源——已删来源仍有历史数据）+ 命中方式多选（字面 / 语义 / 规则）+ 文本搜索（对标题 / 命中词 / 规则名的大小写不敏感子串，300ms 防抖）。过滤与分页在主进程完成（每页 50 条、单次请求上限 200 钳位），结果恒**新→旧**（日倒序、同日内按写入序倒序）；标题可点击打开原帖，推送状态与监控台同款三态（✓ 已推送 / ✗ 推送失败 hover 见原因 / − 静音）。
  - 两个数据面都是手动刷新（历史文件静态，无事件订阅）；统计与列表随「刷新」按钮一起重拉。
- **流水**（Dispositions）："为什么没推送"的观测面——每条**进入处理流**的新帖在每个判定出口的去向记录。
  - **去重语义**：同一帖同一去向**不重复记**（推送失败重试轮、语义未决重评轮每轮重入不刷屏）；去向**变化才追加一条**——同帖形成处置轨迹（如 `语义待判 → 语义未中`、`已挂起 → 已推送`、`推送失败 → 已推送`），按标题找帖子、顺着轨迹看它经历了什么。
  - **14 类去向**：已推送 / 推送失败 / 静音（推送结果组）；来源过滤 / 旧帖 / 置顶 / 排除词 / 相似去重（已拦截组）；未命中 / 语义未中 / 置信度低（未命中组）；已挂起 / 挂起中 / 语义待判（挂起中组）。每条带 detail 小字（命中词、AI 理由、score 与阈值、失败原因等）。
  - **筛选**：去向分组 chips（全部 / 推送结果 / 已拦截 / 未命中 / 挂起中，单选）+ 来源下拉（从数据派生）+ 日期选择。
  - **两个数据面**：日期留空 = **实时视图**（内存环最近 200 条，10 秒自动刷新，页头标"最近 200 条 · 实时"）；选日期 = 读该日的 `pipeline/YYYY-MM-DD.jsonl` 持久化文件（静态，页头标"历史文件"；「回实时」按钮返回）。落盘只记进入处理流的帖子，**保留 7 天**（对齐日志）。
  - 注意：首启基线轮整页只记已读的帖子不经处理流，不产生流水记录；流水与命中记录是两个数据面（命中 = 推送过的帖子，流水 = 全部去向含未推送）。
- **设置**（Settings）分十七个卡片（顺序即页面顺序）：**来源**（置顶）、关键词、**推送通道**、**推送策略**、**Telegram 遥控**、**路由规则**、价格规则、匹配测试台、AI 模型、监控模式、相似降噪、每日总结、轮询、网络（代理）、行为、**数据**、**关于**。底部「保存设置」。要点：
  - **来源**卡（多论坛监控入口）：
    - **已配置来源**列表：类型徽标（NodeSeek / V2EX / RSS）+ 名称（rss 显示 label 或域名）+ 地址 + 「过滤」展开 + 「匹配」展开 + 启停开关 + 删除按钮。默认 NodeSeek 来源不可删除；其余来源也不可删到 0（列表删空保存时会被重置回默认）。启停与增删都是先进 draft、点「保存设置」生效；停用的来源不抓取、也不进外链白名单。
    - **预设来源**：V2EX（官方 API，无需地址）、Linux.do（`https://linux.do/latest.rss`）、LowEndTalk（`https://lowendtalk.com/discussions/feed.rss` 全站）、LowEndTalk Offers（同 feed + 分类白名单只推优惠帖）四个一键添加按钮（旧版预设曾写 `https://lowendtalk.com/feed`（恒 404），v4 配置迁移自动改写为新地址），已添加的按 id 置灰。预设说明如实标注：Linux.do / LowEndTalk 的 RSS 在部分网络会被 Cloudflare 拦截（届时来源状态显示"Cloudflare 拦截"并自动退避，建议配合代理）；V2EX 未认证限速约 120 次/小时（默认 60s 轮询在限内）。
    - **自定义 RSS**：填任意 RSS 2.0 / Atom 地址（前端校验 http(s)，非法红字提示）+ 可选显示名（留空用域名）。来源 id 由域名自动生成（如 `lowendtalk-com`），重复添加同一域名会加 `-2/-3` 后缀区分。
    - **按来源的分类 / 作者过滤**：每行「过滤」按钮展开（一次只展开一个），三个标签输入——分类白名单（非空时只放行命中分类的帖子）、分类黑名单（与白名单并存时黑名单优先）、作者黑名单（一票否决）；分类匹配显示名或 slug、不区分大小写。被滤掉的帖子入去重集、不推送不评估（行为见[匹配语义](#配置项参考)第 1 步）；三列表全空时过滤不落键。
    - **按来源的匹配覆盖**：每行「匹配」按钮展开（与「过滤」互斥单开），顶部**全匹配**开关（开启后该来源新帖全推、下方五项置灰跳过）+ 五段表单——包含关键词（覆盖）/ 排除关键词（覆盖）/ 匹配模式（跟随全局 / 字面 / 语义 / 字面+语义四选一）/ 兴趣描述（覆盖）/ 语义置信度阈值（勾选「覆盖全局阈值」后滑杆可用）。全部留空 = 跟随全局；字段级回退（只覆盖包含词、其余仍用全局是合法形态）。语义见[配置项参考](#配置项参考)的 per-source 匹配覆盖小节。
  - 关键词与兴趣描述均为标签输入：输入后回车添加，点 × 删除。
  - **推送通道**卡（多通道推送入口，取代旧「Telegram 推送」卡）：
    - **通道列表**：类型徽标（Telegram / Bark / ntfy / Webhook）+ 通道 id + **就绪状态点**（绿=就绪：已启用且凭据齐备；黄=凭据齐备但已停用；红=凭据未配齐）+ 启停开关 + 删除 + 「编辑」展开按类型的凭据表单（telegram：Bot Token / Chat ID；bark：Device Key + 可选自建服务器，留空用官方 `api.day.app`；ntfy：Topic + 可选自建服务器，留空用官方 `ntfy.sh`；webhook：接收地址 + 可选 Secret）。**至少保留一条通道**（删空保存时 sanitize 会重置回默认 Telegram 项，UI 直接禁删）。通道 id 是命中明细 `notifyDetail` 的键。就绪判定是主进程 `isChannelReady` 的渲染端复刻（口径以主进程为准）。
    - **添加通道**：类型下拉（Telegram（Bot） / Bark（iOS） / ntfy / Webhook（JSON））→ 按类型填凭据；id 由类型自动生成、冲突加 `-2/-3` 后缀（与主进程 sanitize 同口径，保存后 id 不会被二次改写）。上限 8 条。
    - **代理说明**：Telegram 恒走「网络」页配置的代理；Bark / ntfy / Webhook 在"仅 Telegram 走代理"时与站点抓取 / AI 同待遇**直连**，"全部走代理"时才走代理。
    - **测试推送**：按钮宿主在本卡——按**已保存**配置向全部就绪通道各发一条测试消息（不走路由规则；表单 dirty 时提示先保存）。
  - **推送策略**卡：模式单选（**实时推送**：命中即推，免打扰窗内除外 / **摘要攒批**：命中先挂起，到间隔后按插入序冲刷——**每条仍独立成消息**，锐评在命中时已生成、冲刷不重打 AI）+ 摘要间隔（1-120 分钟，前端只提示不拦截，保存时钳制）+ 免打扰时段（开关 + 起止时刻；支持跨午夜如 23:00→08:00 表示当晚 23 点到次日 8 点；起止相同视为空区间恒不静默；只作用于实时模式——摘要模式本身已是低打扰形态，quietHours 不叠加）。挂起语义说明见卡内「挂起与重启」提示。
  - **Telegram 遥控**卡（R9，DEC-6）：开关（默认关）+ 允许的 Chat ID 标签输入（回车添加，**上限 10**；群 id 是负数如 `-1001234567890`；推送通道的**主 Chat ID 隐含允许**，无需重复填）。就绪条件 = 开关开且存在凭据齐备的 Telegram 通道（botToken / chatId 均非空）——未就绪时开关可打开但监听不启动；保存即启停（热更新，无需重启）。启用后 bot 长轮询接收指令：`/status`（引擎 / 健康 / 下次轮询 / 累计命中 / 挂起待推 / AI 模式摘要，降级时附注原因）、`/pause`、`/resume`、`/poll`（立即补一轮）、`/help`；群聊指令可带 `@botname` 后缀。**清单外会话一律静默忽略——不回复任何回声**（连 /help 也不回，防陌生人探测 bot 存活）。遥控监听独立于监控暂停状态：`/pause` 之后 `/resume` 仍可达（正是它的用途；同理遥控收发不占用推送队列，长轮询不会拖延命中推送）。**独占提示（卡内如实标注）**：启用后该 bot 的 getUpdates 长轮询被本应用占用——其他轮询同一 bot 的工具 / 残留 webhook 会互相 409（应用启动自动清历史 webhook，运行中遇 409 记日志 + 60s 退避重试；详见故障排查矩阵）。
  - **路由规则**卡：规则列表（when 摘要（来源 / 命中方式 / 价格规则）→ 目标通道摘要 + 删除）+ 添加表单（来源下拉「任意」、命中方式多选（字面 / 语义 / 规则）、价格规则下拉（选中即自动勾选「规则」方式——ruleId 条件只对规则命中生效）、目标通道多选）。校验对齐主进程 sanitize：至少声明一个条件 + 至少一个目标通道，否则「添加」禁用。id 由 `rule-N` 派生去重，上限 20 条。**按列表顺序首条命中生效**（顺序即优先级，需调整优先级时删除重加）；无规则命中走全部就绪通道；测试消息与日报不受路由影响。
  - **价格规则**卡：规则列表（规则名 / 条件摘要 / 「编辑」展开表单 / 启停开关 / 删除）。「编辑」展开行内表单：规则名称（展示用）、周期（不限 / 年付 / 月付）、价格上限 + 币种（不限 / ¥ / $）、流量下限（GB）、关键词前置；数值留空 = 不限（不落键）。上限 20 条；语义与提取口径见[价格规则提取口径](#价格规则提取口径)。
  - **匹配测试台**卡：输入一条帖子标题（+ 可选来源 / 分类 / 作者 / 是否调用 AI），按**已保存**配置逐阶段跑判定管线——来源过滤 → 排除词 → 价格规则 → 全匹配 → 字面 → 相似降噪 → 语义评估，每阶段给出 ✓ 放行 / ✗ 拦截 / – 跳过 / · 无命中 与原因，结论回答「会不会推送」。只读诊断：不写去重集、不推送、不产生命中记录，可反复测试。勾选「调用 AI」会真调一次语义评估（消耗一次 LLM 服务侧调用，但**不计入监控引擎的今日调用计数**）；相似阶段用近 2 天已推标题近似真实窗口，被拦时明细直接给出与哪条已推标题相似及相似度——**推送之后回测同一帖会与它自己相似，属正常现象**。表单有未保存改动时提示先保存。
  - **AI 模型**卡：Base URL / API Key / 模型名三项 + DeepSeek / Kimi / GLM 三个一键预设 + 「测试连接」（按**已保存**配置发一条最小对话，表单 dirty 时会提示先保存再测试）+ 「推送锐评」开关（命中推送附加 AI 一句点评）+ 「锐评深度思考」开关（仅锐评开启时呈现；**默认关 = 直出模式**：AI 直接写一句锐评，快而稳、失败自动重试一次；开启后允许推理型模型如 GLM 先思考再点评，明显更慢且可能因思考占满输出预算而挤不出锐评，仅对支持思考参数的服务生效）。
  - **监控模式**卡：字面匹配 / 语义匹配 / 字面 + 语义三选一（单选卡片），下接兴趣描述输入（建议上限 20 条，超了橙字提示不硬拦）与「语义置信度阈值」滑杆（0–1，默认 0 = 不过滤；调高减少误报但可能漏报，仅作用于 AI 语义档）。**「字面 + 语义」= 关键词优先**：每条新帖先过关键词，命中即推（零 AI 调用）；未命中的才进 AI 语义批。
  - **相似降噪**卡：开关（默认开）+ 相似阈值滑杆（0.50–0.95，默认 0.72；调低拦得更狠但可能误杀正常新帖，调高只拦几乎相同的标题）。只抑制"装饰级"转发变体，换词改写拦不住（见[故障排查矩阵](#故障排查矩阵)）。
  - **每日总结**卡：开关 + 时刻（默认 22:00，本地时区）。日报推送到全部就绪通道（不走路由）。
  - 轮询间隔有 30/60/120 秒快捷按钮；低于 15 秒会红字提示，保存时钳到 15。
  - 代理地址非法（不以 `http://` `https://` `socks5://` 开头）会红字提示，保存时清空。
  - 「发送测试消息」「测试连接」「匹配测试台」用的都是已保存的配置（表单 dirty 时提示先保存再测）。
  - 推送总开关（临时静音：仍记录命中但不推送）、开机自启。
  - **数据**卡（R8 备份与恢复）：「导出备份」把 config / seen / state / feedback 四段打包成单文件 JSON（保存对话框选位置，默认名 `forumwatch-backup-YYYYMMDD.json`；**文件含明文凭据**——bot token / API key，新建即 600 权限，卡内警告与成功提示双重提醒）。「导入备份」两步操作：先点按钮出确认层（覆盖语义 + 重启生效 + 不可撤销），确认后才弹文件选择；主进程验包（不是 ForumWatch 备份 / 格式版本不认识 / 段形状不对 → 红字展示原因），通过后按段原子写回 userData——**需重启应用生效**（内存里的旧配置与已读记录不热换）。seen 段无效时的重基线语义见[故障排查矩阵](#故障排查矩阵)。
  - **关于**卡：当前版本号（来自应用包）+ 更新检查——手动「检查更新」真发一次请求；结果三态展示（**有新版**：附「打开下载页」按钮，经系统浏览器打开 GitHub release 页 / **✓ 已最新** / **检查失败**附原因与时间）。应用启动 15 秒后与每 24 小时自动检查一轮（结果进同一缓存，卡片进入时拉取）；检查失败只记日志，不影响监控。

**托盘**：关闭窗口 = 隐藏窗口，监控继续。托盘菜单：显示主窗口 / 暂停监控（或恢复监控，随状态）/ 立即轮询 / 发送测试通知 / 在 Finder 中打开配置目录 / 退出。macOS 上点击托盘图标切换主窗口显隐；应用不出现在程序坞与 Cmd+Tab（dock 已隐藏，预期行为）。

## 状态模型

### 运行状态（desired × health）

状态由两个正交维度派生：

- **desired**（用户意图，唯一可写）：`running` / `paused`。暂停只停排程，不清任何观测值。
- **health**（内核观测，自动流转）：`ok` / `backoff`（抓取失败退避中）/ `challenged`（被 Cloudflare 挑战）。**聚合 health 取各来源最差**（challenged > backoff > ok）。

UI 与托盘按 desired 优先的顺序展示为四种状态：

| 展示状态 | 含义 | 恢复方式 |
| --- | --- | --- |
| 运行中 | 正常轮询 | — |
| 已暂停 | 用户主动暂停 | 点「恢复监控」 |
| Cloudflare 拦截 | 抓取被 CF 挑战（HTTP 403 或 `cf-mitigated: challenge`），自动退避重试 | 通常自动恢复 |
| 退避重试中 | 网络失败等普通错误，连续失败计数 > 0 | 成功一轮后自动复位 |

注意：系统事件（休眠唤醒、解锁屏幕）触发的补轮询尊重 desired——你暂停了监控，它不会被系统事件偷偷唤醒。

### 来源状态（per-source）

`EngineStatus.sources` 里每个来源独立维护 `health / lastSuccessAt / lastError / consecutiveFailures / cooldownUntil`，各自走同一条退避曲线。聚合字段是全局汇总，监控台的**来源状态块**展示每来源明细（退避中显示剩余倒计时）。调度器间隔恒为配置值——某来源退避/被拦时**只拖慢它自己**（轮询轮内跳过该来源，冷却结束后的下一轮重试），其余来源照常按配置间隔轮询，互不影响。`SourceStatus` 另含 `page2Fetches`（引擎发起"补抓第 2 页"请求的累计次数，内存态、重启清零；当前 UI 未展示）——上一轮有效新帖 ≥ 40 且来源健康时下一轮会请求 2 页，2026-09 复测该补抓对 NodeSeek 实际无效（服务端忽略页码或 403，同页内容自动去重、无害）。

### AI 运行态（AiRuntimeStatus）

语义监控的观测面，展示在监控台 AI 状态块：

| 字段 | 含义 |
| --- | --- |
| `configured` | Provider 三项（baseUrl/apiKey/model）是否齐备 |
| `effectiveMode` | **实际生效**的模式（UI 看这个，不看配置的 matchMode） |
| `degraded` | 降级三态：`none`（正常）/ `unconfigured`（AI 未配置）/ `backoff`（语义评估连续失败退避中，见[语义评估节流与降级](#语义评估节流与降级r13-3)）。无配额降级（不设每日上限） |
| `callsToday` | 今日 AI 调用数（语义评估 + 锐评，锐评一次计入两者；本地自然日滚动，纯观测计数，无上限） |
| `commentaryToday` | 今日锐评调用数（本地自然日滚动，与 `callsToday` 同日翻转；已计入 `callsToday`）。**可选字段**：旧状态快照没有它，等价 0 |
| `lastAiError` | 最近一次 AI 错误（脱敏；评估成功后自动清空） |
| `semanticCooldownUntil` | 退避冷却截止时刻（**可选**，仅 `backoff` 态非 null）。**可选字段**：旧快照容忍缺失 |

降级语义：配置了语义/叠加模式但 `degraded = unconfigured` 时，`effectiveMode` 自动回 `literal`，行为与字面档完全一致；`backoff` 是**临时**降级（冷却结束自动恢复，`effectiveMode` 仍是配置的模式）。AI 评估失败**不计入轮询的 consecutiveFailures**（不影响 health），只记 `lastAiError`。

### 语义评估节流与降级（R13-3，R15 修订）

语义模式下每个过闸新帖都会进 AI 批（批式：≤12 帖 / 次请求、30s 超时——R15 从 15s 放宽：线上实测 12 帖批量经网关到推理型模型常超 15s）。评估请求默认**禁用模型思考**（R16）：请求体同时附三种方言的禁思考参数——`thinking:{type:"disabled"}`（智谱 GLM/OpenRouter）、`enable_thinking:false`（SiliconFlow/DashScope 的 Qwen3 系）、`chat_template_kwargs:{enable_thinking:false}`（vLLM/SGLang）——端点各取所认；严格校验未知参数的端点（如 OpenAI 官方）回 400 时自动去掉参数重试一次并记住该端点（换 provider 配置自动重学），因此**任何填入的模型都可用**。`ai.evaluation.useThinking` 显式 true 才保留模型默认思考行为。为防上游限流或故障时打爆配额、以及未决帖被无限重试后滚出首页静默丢失，引擎有三道保护：

- **指数退避**：评估连续失败时，第 n 次失败后冷却 `30s × 2^(n-1)`（封顶 10 分钟：30s → 1m → 2m → 4m → 8m → 10m…）；上游 429 明示 `retry_after` 时冷却取 `max(自身曲线, retry_after)`（R15）。**冷却期内零调用**——新帖与未决帖都挂起为「语义未决」（去向面板可见），冷却结束随下一轮批量重评；任一批评估成功即全部复位。同轮多批时第一批失败后剩余批次不再打上游（R15 修正：旧版批间不查冷却，一轮会把退避连升数级、白烧调用）。状态卡 AI 块会显示「AI 评估退避中」。
- **未决时间窗（默认 30 分钟，R15）**：同一帖持续拿不到裁决（评估失败 / 回包缺项 / 退避冷却跳过），超过 `ai.semanticUndecidedTimeoutMin` 分钟后**降级字面判定**收口——用该来源的生效包含词做一次字面匹配，命中即推（记「字面」命中）、未中入 seen 并在去向面板记明原因。镜像「AI 未配置整体降级字面」的既有语义：AI 不可用期间不静默丢帖，也不无限烧调用。注意 matchMode=`both` 时降级字面必然未中（能字面命中的帖早在进 AI 批之前就推了），时间窗的意义是给上游故障留足恢复时间。
- **AI 故障告警（R15）**：语义评估连续失败 ≥ 10 分钟 → 经通知通道推一条「⚠️ 语义评估持续失败」（含最近错误与影响说明），恢复时补发「✅ 已恢复」——把「上游余额不足/限流 → 用户不知不觉漏推」变成显性事件。每个故障期最多 1 条告警 + 1 条恢复，不刷屏。

**想从根上减少 AI 调用量**：语义档的调用量 = 进管线的新帖数，与关键词多少无关。真正减量的杠杆是**别让不重要的来源进语义档**——用 per-source 匹配覆盖把闲聊型来源（如 NodeSeek / V2EX）设为「字面匹配」、只留 Linux.do / Offers 这类高价值来源走 AI；或对"全要"的来源开「全匹配」（跳过 AI、零调用）。

### 挂起待推送（EngineStatus.pendingNotifyCount）

免打扰时段内 / 摘要模式下挂起队列（engine 内存 Map `deferredHits`）的当前条数，随每次状态快照下发。**可选字段**：旧状态快照没有它，消费方容忍缺失（等价 0）。挂起的帖子不入已读、不产生命中记录、不入相似降噪窗——到点（免打扰窗尾 / 摘要间隔）冲刷时才推送并补记命中；重启丢队列自愈（语义详见[推送细节](#推送细节)）。挂起条数 > 0 时监控台状态卡下方显示「⏳ 挂起待推送 N 条」行。

### 看门狗（EngineStatus.watchdog，可选）

桌面装配的旁路自愈观测（R8，**仅桌面端**）：主进程每 30 秒检查一次「desired=running 但下次轮询时刻已超期 max(轮询间隔 × 2, 90 秒)」——排程定时器因主进程卡顿等挂死时，自动强制补一轮（runNow）让监控循环重新起步，并记一条 error 日志（60 秒内的重复触发只计数不刷屏）；暂停期间不触发。字段形状 `{ lastTriggeredAt: string | null, count: number }`：null / 0 = 看门狗在位但从未触发。**可选字段**：headless 装配不接看门狗（状态里没有它），消费方容忍缺失。

**两条状态路径的差异（如实）**：该字段由桌面 runtime 在**状态广播**（evStatus 推送）时把实时值附加到快照上下发；`status:get` 拉取路径直读引擎快照，**不带 runtime 侧实时观测**（引擎不写该字段，拉取到的至多是恒 null/0 的占位值）——需要该字段的消费方应以状态广播事件为事实源。当前 UI 未展示它，触发情况看运行日志（`engine watchdog triggered: poll overdue by ...`）。

## 配置项参考

设置全集即 `AppConfig`（`src/shared/types.ts`）。保存时统一过清洗（sanitize），下表列出默认值与清洗规则：

| 字段 | 默认 | 说明 / 清洗规则 |
| --- | --- | --- |
| `includeKeywords` | `[]` | 包含词条。trim、去空、去重（不区分大小写，保留首次写法）。**为空 = 字面档不推送任何帖子**。词条之间任一命中即推（OR）；**词条内部用 `&&` 连接多个词 = 须全部命中**（AND，如 `搬瓦工 && 香港`；全角 `＆＆` 或两边带空格的单个 `&`/`＆` 亦可，单个紧邻的 `&` 如 `AT&T` 是普通字符不拆分）——`(A 且 B) 或 C` 用「`A && B`、`C`」两条词条表达 |
| `excludeKeywords` | `[]` | 排除词条，一票否决。清洗规则同上，词条内 `&&` AND 语义同上（须全部出现才否决）。**语义模式下仍先于 AI 生效** |
| `pollIntervalSec` | `60` | 轮询间隔（秒）。非法值回退 60；小于 15 钳到 15 |
| `proxyUrl` | `''` | 代理地址。必须以 `http://` `https://` `socks5://` 开头（忽略大小写），否则置空（直连） |
| `proxyScope` | `'telegram-only'` | 代理作用域：`telegram-only`（仅 Telegram **通道**走代理；**来源抓取、AI 请求与 Bark / ntfy / webhook 通道直连**）/ `all`（全部请求走代理，含来源抓取、AI 与全部推送通道）。非法值回退 `telegram-only` |
| `channels` | `[{id:'telegram', type:'telegram', enabled:true, botToken:'', chatId:''}]` | 推送通道列表（判别联合：telegram / bark / ntfy / webhook，按 type 分派；**取代旧顶层 `telegram` 段**，旧凭据加载时自动映射进 channels[0]，见[本地数据文件](#本地数据文件)）。清洗：非数组 / 全弃 → 回默认单项（**列表恒至少保留一条**，空通道列表会让"是否已配置"判定永久悬空）；**上限 8 条**（超出截断）；逐项按 type 重建——telegram：botToken / chatId trim（**空凭据合法** = 未配置态）；bark：deviceKey trim（空保留）、serverUrl 非 http(s) **弃字段**（缺省 = 发送端用官方 `https://api.day.app`）；ntfy：topic trim 且**非空否则整项弃**（无可推送目的地）、serverUrl 同 bark（缺省 = `https://ntfy.sh`）；webhook：url 必须合法 http(s) URL 否则**整项弃**、secret trim 空不落键；enabled 布尔化（`=== true`）；未知 type / 非对象整项弃；id slug 化去重、缺 id 按类型派生默认名、冲突追加 `-2`/`-3`。旧顶层 `telegram` 键不在 sanitize 白名单——**写路径只写新形状**，旧盘加载/保存一次后该键自然消失 |
| `notify` | `{mode:'instant', digestIntervalMin:15, quietHours:{enabled:false, startHHMM:'23:00', endHHMM:'08:00'}}` | 推送策略：`mode` 只认 `'instant'` / `'digest'`，非法回 `'instant'`；`digestIntervalMin` 非法（非数字/NaN/Infinity）回 15、钳到 [1,120] 分钟；`quietHours.enabled` 布尔化、`startHHMM` / `endHHMM` 格式非法（复用 HH:MM 校验口径：时 0-23 / 分 0-59）分别回 `'23:00'` / `'08:00'`。免打扰窗为本地时区**半开区间 [start, end)**（恰在 start 窗内、恰在 end 窗外）；跨午夜（start > end，如 23:00-08:00）合法；**起止相等 = 空区间恒不静默**（防配置错误变全天静默）。quietHours 只作用于 instant 模式——digest 本身已是低打扰形态，不叠加 |
| `notify.remoteControl` | `{enabled:false, allowedChatIds:[]}` | Telegram 遥控（R9，DEC-6）。`enabled` 布尔化（`=== true`，**默认关**）；`allowedChatIds` 每条 trim、去空、**精确去重**（chat id 是数字串，负数群 id 原样合法——不做大小写折叠）、**上限 10 条**（超出截断）。主 Chat ID（第一个凭据齐备的 telegram 通道的 chatId）由遥控控制器现读凭据时隐含合并，不进列表；就绪条件 = enabled 且该凭据非空（缺一监听不启动）。指令与 allowlist 语义见[界面导览](#界面导览)的遥控卡；**启用后本应用独占该 bot 的 getUpdates**（其他 getUpdates 消费者互相 409，见故障排查矩阵）。加法字段，schemaVersion 不 bump |
| `routing` | `[]` | 路由规则（声明式首条命中）：非数组 → `[]`（空 = 不路由，全部命中走全部就绪通道，合法状态）；**上限 20 条**（超出截断）。每条 `{id, when, channelIds}`：`when.sourceId` 悬挂（不在 sources）**剔字段**（不是整条弃——条件可能只是暂时悬挂）、`when.matchedBy` 枚举过滤（合法值 literal/semantic/rule，清洗后空数组不落键）、`when.ruleId` 悬挂（不在 priceRules）剔字段；when 清洗后**全空 → 整条弃**（无条件无法判定）；channelIds 只保留存在于 channels 的 id（顺序保留、去重），过滤后空 → 整条弃；id slug 化去重。执行：按序评估、声明的条件之间 AND、**首条命中**即得该规则的 channelIds；无命中走默认 = 全部就绪通道；测试消息与日报**不走路由**（恒广播） |
| `notifyEnabled` | `true` | 推送总开关。关闭后命中仍会记录到「最近命中」与 `hits/`，但不推送 |
| `launchAtLogin` | `false` | 开机自启。mac 上未签名应用可能被系统拒绝 |
| `sources` | `[{id:'nodeseek', type:'nodeseek', enabled:true}]` | 论坛来源列表（v3 起为按 type 判别的联合；关键词全局共享，per-source 过滤见下一行 filters）。`type` 三种：`nodeseek`（SSR 页面抓取）/ `v2ex`（官方 API）/ `rss`（额外必带合法 http(s) 的 `url`、可选 `label` 展示名）。清洗：非数组/空回默认单项；未知 type 整项丢弃；rss 的 url 非法（非 http(s) / 解析失败 / 无 host）整项丢弃；label trim 后为空视为无；id 规范成 slug（缺 id 时 rss 从 url 域名派生建议 id）、enabled 布尔化、按 id 去重保留首个；全部项非法回默认单项，绝不落空列表 |
| `sources[].filters` | （可选，缺省无） | per-source 过滤（**引擎已消费**，管线第 1 步）：`includeCategories`（分类白名单，空/缺失=不限；匹配分类**显示名或 slug**，大小写不敏感、字面相等——非子串/正则）、`excludeCategories`（分类黑名单，命中任一否决；与 include 同时给出时 exclude 优先）、`blockedAuthors`（作者黑名单，命中任一一票否决）。被滤帖入 seen 不推送不评估。三列表各自 trim、去空、大小写不敏感去重、每列表上限 100 条；清洗后全空不落键 |
| `sources[].matching` | （可选，缺省无） | per-source 匹配覆盖（R13，引擎经 matching.ts 的 `resolveSourceMatching` 解析，测试台 / 统计共用同一实现）：五个**全可选**字段，字段级回退全局——`includeKeywords` / `excludeKeywords`（清洗规则同全局关键词，清洗后空数组不落键 = 未覆盖；设置后**替换**而非合并全局同名列表）、`matchMode`（枚举非法/缺失不落键，**不回 'literal'**——覆盖里非法 = 用户没想覆盖）、`interests`（清洗同全局口径：每条 trim、单条 ≤500 字符、≤20 条）、`semanticThreshold`（**仅有限数字才落键**，钳 [0,1]；非法 = 不落键 = 跟随全局，与全局"非法回 0"有意不同）。清洗后全空不落键。第六字段 `matchAll`（R13-2，仅 `true` 落键）= 来源级全匹配：过闸新帖直接命中（matchedBy='matchall'），字面/语义档跳过。语义细节与限制见[下方小节](#per-source-匹配覆盖)与[来源级全匹配](#来源级全匹配r13-2) |
| `priceRules` | `[]` | 结构化价格规则（第三种命中方式 `matchedBy='rule'`，条件 AND、首条命中即得；提取口径见[价格规则提取口径](#价格规则提取口径)）。每条：`id`（slug 化、全列表去重）、`label`（trim、空则不落键）、`enabled`（缺省 false）、`cycle`（`yearly`/`monthly`/`any`，非法回 `any`）、`currency`（`CNY`/`USD`/`any`，非法回 `any`）、`maxPrice`/`minTrafficGB`（非有限正数丢字段）、`keywords`（AND 前置，词条任一命中、词条内 `&&` 须全部命中（口径同 `includeKeywords`），trim/去空/大小写不敏感去重/**每规则上限 20**，清洗后空不落键）。非数组回 `[]`（空列表 = 无规则，合法状态）；整条非对象/无可用 id 丢弃；**列表上限 20 条**（超出截断）。任一条件都不声明的 enabled 规则 = 全匹配（由用户自己负责） |
| `similarity.enabled` | `true` | 相似降噪开关，**默认开的布尔之一**（缺失/非法不会静默关掉，显式 `false` 才是关）。关闭后命中帖推送前不再与已推窗口比对，行为与升级前一致 |
| `similarity.threshold` | `0.72` | 相似阈值（标题归一化后 3-gram Jaccard ≥ 阈值判相似）。非法回 0.72，钳到 [0,1] 保留两位小数；UI 滑杆范围 0.50–0.95。48h 对比窗口时长是引擎常量，不进配置 |
| `ai.provider.baseUrl` | `''` | OpenAI 兼容服务地址，如 `https://api.deepseek.com/v1`。trim、去尾斜杠、必须 `http(s)://` 开头否则置空；请求时拼 `/chat/completions` |
| `ai.provider.apiKey` | `''` | 服务商 API Key，trim。仅存本机 `config.json`（600 权限） |
| `ai.provider.model` | `''` | 模型名（如 `deepseek-chat`），trim |
| `ai.matchMode` | `'literal'` | 监控模式：`literal`（字面）/ `semantic`（语义）/ `both`（字面+语义，任一命中）。枚举非法回 `literal`。Provider 未配置时实际生效回 `literal`。**价格规则不受此门控**（独立通道，semantic-only 下同样生效） |
| `ai.semanticThreshold` | `0` | 语义置信度阈值：AI 判 hit 且 `score ≥ 此值` 才推送；默认 0 = 不过滤（行为不变）。非法回 0、钳到 [0,1]（不取整）。**旧模型不回 score 时按 1.0 兼容**——此时阈值实际不起作用（见故障排查矩阵）；已在推送重试缓存中的帖子沿用判定时的阈值，不受热更新影响 |
| `ai.interests` | `[]` | 兴趣描述（语义监控用）。每条 trim、去空、单条超 500 字符截断、**最多保留 20 条**。为空时语义档永不命中 |
| `ai.dailyReport.enabled` | `false` | 每日总结开关，强制布尔 |
| `ai.dailyReport.timeHHMM` | `'22:00'` | 日报时刻（`HH:MM`，本地时区）。格式非法（时 0-23 / 分 0-59 之外）回 `'22:00'` |
| `ai.commentary.enabled` | `true` | AI 锐评开关（命中推送附加 💬 点评行），强制布尔。**默认开的布尔之一**（与 `similarity.enabled` 并列，全配置仅此两个）。需要 AI Provider 已配置才实际生效；与语义评估均无每日次数上限（调用成本由 LLM 服务侧计费约束） |
| `ai.commentary.useThinking` | `false` | 锐评思考开关（R12），强制布尔、**默认 false = 直出模式**：请求附思考禁用参数（仅智谱 GLM 系等支持的服务生效）、max_tokens 200、失败自动重试一次。显式 `true` = 思考模式（推理型模型先思考再点评：max_tokens 2000、单发不重试，更慢且思考可能吃光预算导致空评） |

匹配语义（只匹配标题；AI 语义评估看标题与分类，价格规则同样只看标题）。一条**新帖**从抓取到推送经过的判定管线，按顺序：

0. **挂起队列成员检查**（第六轮）：该帖已在免打扰 / 摘要挂起队列（`deferredHits`）→ **整帖跳过**——不重新匹配、不重评估、不入 seen，等队列冲刷收口。不拦的话免打扰结束的那一轮会绕过队列直接即时推送，与冲刷**双发**。此检查先于一切其他步骤、覆盖全部命中方式。
1. **per-source 过滤**：该来源配了分类白/黑名单或作者黑名单且帖子被滤（分类匹配显示名或 slug、大小写不敏感、字面相等）→ 入 seen，不推送不评估。
2. **id 阈值旧帖**（仅声明"帖子 id 随创建递增"的来源：NodeSeek / V2EX；RSS 不做）：unseen 且数值 id ≤ 该来源 `maxSeenTopicId` → 被回复顶起的旧帖，入 seen 不推送。
3. **置顶**：置顶帖是旧帖，入 seen 不推送（仅 NodeSeek 有此概念）。
4. **排除词**：标题命中任一排除词 → 一票否决（先于一切命中方式；语义模式下同样否决）。
5. **价格规则**：`priceRules` 非空时逐条评估（条件 AND、首条命中即得）→ 命中即推送（`matchedBy='rule'`，推送显示「🎯 命中规则: 规则名」），**短路字面与语义**（同一帖只记一种命中方式，规则优先）；**不受 matchMode 门控**（semantic-only 下同样生效）。提取口径见[价格规则提取口径](#价格规则提取口径)。
6. **字面匹配**：生效模式含 `literal` 时，包含列表为空 → 永不匹配；词条任一命中 → 推送（词条内 `&&` 连接的多个词须全部命中），命中的词条（去重、原始写法整条）记入 `matchedKeywords` 并出现在推送消息里。
7. **相似降噪闸**：规则 / 字面 / 语义**任一命中**的帖子，推送前与近 48 小时**成功推送过**的标题比对（`similarity.enabled`，默认开）——相似 → 入 seen 不推送（日志 `similar topic swallowed`，处置流水 detail 带**命中的已推标题与相似度**，测试台拦截明细同款），被吞帖不生成锐评、不产生命中记录。只拦"装饰级"变体，边界见故障排查矩阵。
8. **语义批（置信度闸）**：生效模式含 `semantic` 且字面未命中的帖子送 AI 批量评估（每批 ≤ 12 帖一次请求）；判定 hit 且 `score ≥ ai.semanticThreshold` → 过第 7 步相似闸后推送并附 AI 理由（`semanticReason`）；判定不相关、**或 hit 但 score < 阈值**（按不相关处理，入 seen 不再重评）；**评估未决（超时/响应异常）不记已见**，下轮自然重评，滚出首页即止。

规则 / 字面 / 语义任一命中且未被相似闸拦下 → 走推送。推送前还有一道**推送策略闸**（decideNotifyAction）：免打扰窗内（instant 模式）或摘要模式（digest 恒挂起）→ 命中**挂起**（不入 seen、不产生命中记录、不入相似窗），等免打扰窗尾 / 摘要到点冲刷——挂起与冲刷语义见[推送细节](#推送细节)。价格规则与字面命中的帖子在遍历中即时推送（页面旧→新）；语义命中在其后按批内顺序推送。

保存即生效：引擎每轮轮询前重读配置，各通道发送前重读凭据，路由每次发送现读规则，代理客户端随配置变更销毁重建。无需重启应用（例外：已在语义推送重试缓存中的帖子沿用判定时的置信度阈值）。

上面管线的每个出口（以及挂起 flush 收口）都会向「流水」页记一条处置去向——同帖同去向不重复记、去向迁移才追加（去重语义与 14 类去向见[界面导览](#界面导览)的流水页），按帖回溯"它走到了哪一步"。

### per-source 匹配覆盖

单个来源可以在「设置 → 来源 → 该行『匹配』」面板覆盖五个匹配输入（`sources[].matching`），**字段级回退**：未设置（或清洗后为空不落键）的字段跟随全局同名配置，设置了的就是**替换**而非合并——该来源的包含词 / 排除词 / 匹配模式 / 兴趣描述 / 语义置信度阈值与全局无关地生效。典型用法：LowEndTalk Offers 来源只关心 VPS / 独服关键词 + 一段专属兴趣描述，全局关键词保持宽泛给其他来源用。

覆盖作用于管线的这些位置：语义档门控（含 matchMode 覆盖后的字面档跳过）、排除词否决（第 4 步）、字面匹配（第 6 步）、语义批的兴趣与置信度闸（第 8 步）。测试台与关键词零命中统计按同一解析器取生效值——测试台选了来源时给出的是**该来源视角**的判定。

限制与口径（务必读）：

- **「显式清空包含词」不可表达**——清空后不落键 = 回退全局列表，不是"该来源字面档永不命中"。想让某来源只走 AI 判定，把它的匹配模式覆盖为**语义匹配**（字面档整体跳过，标题含不含任何词都不再走字面命中）。排除词同理无法表达"该来源不排除"。
- **价格规则与 AI 锐评不参与覆盖**——恒用全局配置（价格规则命中不受 matchMode 门控，锐评开关 / 思考模式对全部来源一致）。
- **Provider 未配置的整体降级仍是全局判定**：AI 三项没配齐时，该来源即使覆盖了 `matchMode: 'semantic'` 也会降级为字面档（镜像全局降级语义，防止配了语义模式却没配模型时静默丢帖）。
- **观测面口径差**：托盘 / 监控台的 AI 状态块显示的"生效模式"仍是**全局** `ai.matchMode`——某来源配了 `matchMode` 覆盖后，该来源的实际门控可能与显示值不符。想知道某来源实际怎么判，用匹配测试台选该来源跑一遍。

### 来源级全匹配（R13-2）

「匹配」面板最上方的**全匹配**开关（`sources[].matching.matchAll`）：开启后该来源所有过闸新帖**直接命中推送**（命中方式记「全匹配」，历史 / 路由 / 统计里都是独立一档），关键词、匹配模式、兴趣、阈值全部跳过（面板上这五项随之置灰）；价格规则仍先评估——命中规则的帖照旧记「规则」，保留规则归因与按规则路由的能力。

**全匹配 ≠ 全推送**，这些闸照常否决：排除词（全局或该来源覆盖的都算）、分类 / 作者过滤、旧帖阈值 / 置顶、相似降噪。典型用法就是 LowEndTalk Offers 开全匹配：优惠版块的帖子全要，再用排除词（如 `giveaway`）与分类白名单做减法。注意推量：高频版块开全匹配 = 每帖必推，AI 零调用（语义档整体跳过，不烧配额），但推送通道的量会如实放大。

### LowEndTalk Offers 使用说明

「设置 → 来源 → 预设来源」的 **LowEndTalk Offers** 一键添加（仍需保存生效）：同一个全站 feed（`https://lowendtalk.com/discussions/feed.rss`）+ 分类白名单 `Offers / Shared Hosting Offers / Giveaways & Freebies`（只推优惠类帖；白名单保存后可在该行「过滤」面板自行增删，比如加 `Dedicated Hosting Offers`）。用全站 feed 而非优惠分类端点，是因为后者被 Cloudflare 拦截的策略时变、全站 feed 稳定——分类过滤在本地完成（RSS `<category>` 匹配显示名或 slug，零额外请求）。网络方面与全站预设同款：部分网络会被 Cloudflare 拦截，建议配合代理。

进阶用法是配合 per-source 匹配覆盖：该行「匹配」面板把包含词覆盖为 `VPS / dedicated server` 之类的优惠专属词、兴趣描述覆盖为羊毛向的一句话——这个来源从此只按自己的词与兴趣推送，不影响其他来源的全局配置。

**与全站「LowEndTalk」来源并存的双推语义**：两个预设 id 不同（`lowendtalk` / `lowendtalk-offers`，可同时添加），但读的是同一个 feed——同一帖会在两个来源各命中一次，去重键带来源前缀拦不住跨源重复（D2/D3 设计）。默认相似降噪（标题级、0.72 / 48h 窗口）会吞掉第二次推送（同帖标题归一后相似度 1.0 必命中），**但关闭相似降噪后该兜底即失效**。建议二选一：要么只开 Offers 预设，要么开全站预设后把 Offers 停用。

### 价格规则提取口径

从帖子标题提取结构化交易信息（周期 / 价格 / 流量），与规则条件做确定性比对。总原则 **「宁缺勿错」**：识别不了的写法不产出字段、规则不命中，而不是猜一个近似值去比较。

| 字段 | 认这些写法 | 不认这些 |
| --- | --- | --- |
| 周期 | `年付` `每年` `包年` `3年` `1,299元/年` `annual` `per year` `yearly`；`月付` `每月` `15元/月` `monthly` `per month`、独立词 `mo` | 半年付 / 季付 / 双月付（不识别） |
| 价格 | `¥99` `￥99` `99元` `99 块`（人民币）；`$9.9` `9.9刀` `USD 20`（美元） | **裸数字**（如「年付88」的 88，无币种标记不算价格）；多价格标题只取首个 |
| 流量 | `500G/GB`、`0.5T/TB`、`1024M/MB`（自动换算成 GB 再比较） | `2C2G` 里的 2G（那是内存）、`500Mbps`（那是带宽）；「不限流量」视为无约束 |

示例（规则：周期 = 年付、价格上限 ¥100、流量下限 500G）：

| 标题 | 提取结果 | 判定 |
| --- | --- | --- |
| `年付 ¥99 的 VPS，500G 流量` | 年付 · ¥99 · 500G | 命中 |
| `[分享] 年付 ￥99 的 VPS 500G！！` | 同上（装饰符不影响提取） | 命中 |
| `月付 $9.9 512M 小鸡` | 月付 · $9.9 · 0.5G | 不命中（周期 / 价格 / 流量均不满足） |
| `年付88 拿下` | 年付（无价格） | 不命中（88 是裸数字，提取不到价格） |

补充：每条规则可配 keywords 前置（AND 条件，缩小范围）；一条规则所有条件都留空 = 全匹配（是否这样用由用户自己负责）；规则命中后短路字面与语义评估（同一帖只记一种命中方式，规则优先）。规则总不命中时，把目标标题丢进「设置 → 匹配测试台」——价格规则阶段会显示从该标题实际提取出的周期 / 价格 / 流量。

headless 模式使用独立数据目录（见下文），与桌面版互不共享。

## 轮询、退避与防休眠

- 每轮间隔 = 配置值 × (1 ± 20% 随机抖动)，下限 15 秒。抖动是为了避免固定频率被识别为机器行为。
- 连续失败时按 `间隔 × 2^n` 指数退避（n = 连续失败次数），封顶 30 分钟；任一轮成功即复位为配置间隔。
- 挑战（challenged）与普通失败走同一退避曲线，只是状态展示不同。
- 不用 `setInterval`：每轮完成后按 `当前时刻 + 间隔` 重排，休眠/壁钟漂移不积累误差；系统唤醒/解锁屏幕时立即补一轮。
- macOS 上监控运行期间阻止 App Nap（`prevent-app-suspension`），暂停/退出时解除。

## 推送细节

### 多通道扇出与聚合

一次命中先经**路由**决定发往哪些通道：按 `routing[]` 列表顺序逐条评估（条件之间 AND），**首条命中**的规则的 `channelIds` 即目标；无任何规则命中（含未配规则）→ 目标 = **全部就绪通道**（就绪 = enabled 且凭据齐备，只有就绪通道会参与扇出）。随后**逐通道串行**发送（保序，且避免多通道并发打爆共享代理）；一个通道失败不连坐，继续发其余。

**聚合语义（any-success）**：任一通道投递成功 → 该条命中记为推送成功（入已读集、计命中）；**全部目标通道都失败**才算推送失败（记 `notifyError`，进既有"下轮重试"路径）。已知取舍：单通道部分失败时其余通道已收到，下轮重试会把同一条再推给已成功的通道——宁可重复不可漏推。目标为 0 个通道（规则指向的通道无就绪发送器）→ 按失败处理（`no channel available`）。

**per-channel 送达明细（`HitRecord.notifyDetail`）**：每个通道发送的最终结果（成功/失败与错误）以通道 id 为键记入命中记录（至少一个通道尝试过才落键；静音路径无键）。聚合 `notifyError` 取**首个失败通道**的错误。**测试消息与每日日报不走路由**——恒广播全部就绪通道。

### 各通道的消息形态

- **Telegram**（HTML parse_mode，用户内容全部转义）：

  ```
  🔔 <标题加粗>
  📄 摘要（可选，见下）
  📁 分类 · 👤 作者
  🎯 命中: 关键词1, 关键词2
  🔗 打开帖子（链接）
  ```

  语义命中的推送把「🎯 命中」行替换为 `🎯 语义命中: {AI 判定理由}`（理由截 120 字符、转义；AI 未给理由时仅显示 `🎯 语义命中`）——语义推送不再出现空白的「🎯 命中: 」行，与 Bark/ntfy 的 `· 语义命中: {理由}` 同口径。规则命中（`matchedBy='rule'`）则把「🎯 命中」行替换为 `🎯 命中规则: {规则名}`（规则的 label，未填 label 时用规则 id；转义后）。
- **摘要行（📄）**：来源提供了帖子正文时（RSS `description` / Atom `summary`、V2EX `content`；NodeSeek 列表页没有正文，不写），命中消息在标题之后多一行 `📄 {摘要}`（剥 HTML、压缩空白、截 160 字符，转义后）。动机：Telegram 的富预览卡片由其服务端抓目标页生成，抓取失败（站点拦 Telegram 爬虫）时消息只剩三行、显得异常短小——摘要让消息正文自含内容，不再依赖预览成败。
- **AI 锐评行（💬）**：开启「推送锐评」且生成成功时，命中消息在「🎯 命中」行之后多一行 `💬 锐评: {一句话点评}`（≤80 字符，转义后）。未开启 / AI 未配置 / 本次生成失败时整行省略，消息回退纯净格式——锐评绝不影响推送本身。字面命中与语义命中都会带锐评（独立于匹配模式）。
- **Bark / ntfy**：标题 = 帖子标题（截 60 字符），正文一行摘要 `[分类] 作者 · 命中: 词` / `· 命中规则: 规则名` / `· 语义命中: 理由`；点开跳原帖（Bark 带 url 字段，ntfy 带 click）。
- **Webhook**：结构化 JSON POST——`{type:'hit', topic:{title,url,author,category,categorySlug,sourceId,excerpt?}, matchedBy, matchedKeywords, matchedRule, semanticReason, commentary, ts}`（命中字段全量；matchedBy 由内容推导：有词→literal、有规则→rule、否则 semantic）；日报/测试走 `{type:'raw', text, ts}`。配置了 secret 时每次请求带 `X-ForumWatch-Secret` 头；**单次请求 5 秒超时**（自建消费端慢响应不拖推送线程）。

### 重试、限流与防抖（按通道类型分档）

- **Telegram**：串行队列，两次实际发送间隔 ≥ 1050ms（官方限制约 1 条/秒，留余量）；429 读取响应里的 `parameters.retry_after`，等待该时长（+0.5s 余量，封顶 60s）后重试。一轮命中多条时按旧→新顺序排队推送。
- **Bark / ntfy / webhook**：串行队列 + 两次实际发送间隔 ≥ 200ms 的温和防抖（无单 chat 硬限速）。Bark 的成功口径比 2xx 更严——网关 HTTP 200 时业务码也可能非 200（如 deviceKey 失效），须响应 JSON `code === 200` 才算成功；ntfy / webhook 成功 = HTTP 2xx。
- 全部通道：其他失败（网络异常 / 非 2xx / Bark 业务码非 200）最多 3 次尝试（间隔 1s / 2s），仍失败记入该条命中的 `notifyError` 并在日志写明原因，不影响本轮其他帖子。

### 推送策略：免打扰与摘要（挂起状态机）

- **判定**（每次命中推送前，在相似闸与锐评生成之后）：`digest` 模式恒挂起（quietHours 不与 digest 叠加）；`instant` 模式且免打扰开启且当前在窗内 → 挂起。免打扰窗为本地时区半开区间 [start, end)：恰在 start 窗内、恰在 end 窗外；跨午夜（23:00-08:00）合法；**起止相等 = 空区间，恒不静默**（配置错误自然失效而不是全天静默）。
- **挂起语义**：挂起帖**不入已读**（否则下轮被当旧帖吞掉）、**不产生命中记录**（否则每轮重复落盘）、**不入相似降噪窗**（没推过不算"已推"）；锐评在命中时已生成并随队列保存，冲刷不重打 AI。挂起条数实时显示在监控台状态卡下（`⏳ 挂起待推送 N 条`）。
- **冲刷（flush）只随轮询 piggyback**：无独立定时器——暂停监控期间无轮询即无冲刷，恢复后首轮补发。digest 批窗口从本批第一条挂起起算（或上次冲刷时刻），到 `digestIntervalMin`（1-120 分钟，默认 15）即冲刷；instant 模式的挂起条目在窗尾（或免打扰被热更新关掉）后的首轮冲刷。冲刷**逐条**推送（按挂起顺序，每条独立成消息——不是合并成一条汇总）；成功 = 补入已读 + 记命中（notifiedAt=冲刷时刻）+ 入相似窗；失败重试，**3 次后落 `notifyError` 终态并补入已读**（防重新匹配死循环）；冲刷时刻已静音（推送总开关关闭 / 无就绪通道）→ 按静音终态出队，不重试。
- **24h 超时**：挂起超过 24 小时的条目按 `notifyError='deferred timeout'` 落终态收口（有界内存；无论帖子是否还在首页）。
- **重启丢队列（自愈）**：挂起队列是内存态，重启即丢——未入已读的挂起帖若仍在第 1 页，重启后会被重新匹配（窗内重新入队、窗外直接即时推送），**不丢推也不双发**；已滚出第 1 页的挂起帖重启后自然消失。

### 其他推送规则

- 置顶帖跳过推送（旧帖，只入去重集）。
- 首启基线：首次抓到的整页帖子全部只入去重集、不推送（防通知风暴），日志可见 `baseline captured (N topics)`。
- 每条命中同时落盘 `hits/<本地日期>.jsonl`（见[本地数据文件](#本地数据文件)），是每日总结的数据源。
- 配置热更新：通道凭据 / 启停 / 路由规则保存即生效（发送与路由都现读配置）；只有**就绪通道集合本身变化**（新增/删除/就绪态翻转）才会重建扇出，中断在途发送。

## AI 语义监控与每日总结

**配置入口**：「设置 → AI 模型」填 Base URL / API Key / 模型名（任何 OpenAI 兼容的 chat/completions 服务均可），内置一键预设：

| 预设 | Base URL | 模型 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| Kimi | `https://api.moonshot.cn/v1` | `kimi-k2-0711-preview` |
| GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4.7` |

点预设只填地址与模型名，API Key 需自备；填完点「测试连接」（按**已保存**配置发一条最小对话验证）。监控模式在「设置 → 监控模式」三选一：字面 / 语义 / 字面+语义（字面命中不再送 AI，省调用）；每日总结在「设置 → 每日总结」开关 + 时刻。

**兴趣描述写法**（标签输入，最多 20 条，每条一句自然语言）：要点是说清楚"你要什么"而不是罗列关键词——关键词是字面档的事，兴趣描述给 AI 看场景和意图。示例：

- `Oracle 免费 ARM 的羊毛`——比关键词 `ARM` 精准，能框住"OCI 白嫖服务器"这类说法
- `各大云厂商的低价新用户活动，年付 100 元以内的小鸡`——价格区间、对象、用途都交代了
- `K8s / 虚拟化相关的折腾教程，排除纯广告`

本节其余内容是该体系的行为语义。

### 语义评估管线（每轮轮询内）

1. 前置闸先于 AI（完整顺序见[配置项参考](#配置项参考)的匹配语义管线）：per-source 过滤、id 阈值旧帖、置顶、排除词一票否决；价格规则命中的帖子**不进 AI 批**（命中即得、规则优先）。
2. 字面匹配；`both` 模式下字面命中即推送、**不再送 AI**。
3. 剩余新帖按每批 ≤12 条切片送 AI 批量评估（一次 chat 请求，15s 超时，内联等待）。裁决带 `score`（0-1 置信度；**模型不回 score 时按 1.0 兼容**，与真实 1.0 不可区分）。
4. 判定 `hit` 且 `score ≥ ai.semanticThreshold` → 过相似降噪闸后推送（`matchedBy='semantic'`，带 AI 理由）；判定不相关、或 hit 但 score < 阈值 → 记为已见、不再重评（低置信 hit 不推送、只 log 一条观测）；**未决**（超时/响应异常/缺 id）→ 不记已见，下轮重评，滚出首页即止。
5. 调用按本地自然日滚动**纯计数**（失败调用也计数），不设每日上限——无配额降级语义；实际调用频率受轮询间隔与每批 ≤12 条约束，超量风险由 LLM 服务侧计费/限流兜底。

### 降级与失败语义

- Provider 三项未填齐 → `degraded='unconfigured'`，语义/叠加模式实际按字面跑。
- AI 单次评估失败 → 记 `lastAiError`（脱敏），**不计入轮询失败**（health 不受影响）；帖子按"未决"处理下轮重评。
- 兴趣描述为空 → 语义档永不命中（镜像字面档"关键词为空不推送"的防风暴规则）。
- 置信度阈值只作用于语义档（字面与价格规则命中不受影响），且是推送时判定——已在推送重试缓存中的帖子沿用判定时的阈值，热更新阈值对它们不追溯。

### 反馈闭环

监控台「最近命中」每行尾部的 👍/👎 按钮把你的口味喂给语义评估（B3/DEC-5）：

- **三态操作**：未投时点 = 记票（👍 正例 / 👎 负例）；已投当前方向（按钮高亮）再点同方向 = **撤销**（幂等）；已投另一方向时点反向 = **改票**（覆盖方向、刷新标题与时间——同帖只占一票）。按钮高亮是**会话级**的（重启后清空、不回读盘上的票；投票本身持久生效，与高亮无关），提交失败静默回滚（console 警告，不打断 UI）。
- **持久化**：票落本机 `feedback.json`（形状与容错见[本地数据文件](#本地数据文件)）——正/负例**各 100 条环形**，独立计数、超限淘汰该方向最老；改票只占新方向一个名额。
- **注入语义**：每次语义评估的 system prompt 尾部附**最近 ≤8 条负例**（"用户明确表示不想要，判定时宁可判不相关"）+ **最近 ≤8 条正例**（"用户明确表示想要，同类新帖可判相关"）。每次评估现读——**投票 / 改票 / 撤销后，下一次语义评估即生效**。护栏：标题剥离换行（防帖子标题里的换行伪造提示词列表项）、注入段总长 2000 字符、超限按条整条截断（不截半条）。
- **只影响语义档**：反馈只经评估提示词生效——字面关键词与价格规则的命中**不受影响**；没有票（未投 / 全撤销）时提示词与无反馈功能时逐字节一致。
- **数据流向**：投过票的帖子标题只存本机 `feedback.json`，并随后续语义评估请求发往**你配置的 LLM 服务**（每方向最多注入最近 8 条；撤销后不再注入），不发往其他任何地方。

### 每日总结行为

- 触发：到设定时刻（本地时区）且当天 `reports/<今天>.md` 不存在且 desired==='running'。应用启动/唤醒时补检查，**只补当天、不回溯历史**；当天自动生成失败最多重试 3 次（防死循环）。
- 内容：读当天 `hits/<今天>.jsonl` → LLM 总结成中文 markdown → 写 `reports/<今天>.md` → 推送全部就绪通道。
- 零命中：固定文案"今日无命中"，不调 LLM，照常推送（心跳）。
- 推送：走 `sendRaw` 纯文本通道，**广播全部就绪通道（不走路由）**，复用各通道串行队列与防抖；超过约 3500 字符按行分段（尾缀"（续 N）"）；推送失败只记日志，日报文件不受影响。
- 手动生成：「今日回顾」页「立即生成」随时可出当天日报，**覆盖**已有当天文件（重新生成语义）。
- LLM 失败：自动降级为机械拼接模板（标题列表式），日报不断档。

## headless 模式

不经 Electron、在 node 下直跑监控内核（`scripts/headless.ts`），适合服务器部署、冒烟验证与调试：

```bash
npm run engine:headless -- --once                          # 单轮冒烟，默认目录 ./data/headless
npm run engine:headless -- --config /tmp/nsm-smoke --once  # 指定数据目录
npm run engine:headless -- --config ./data/headless        # 常驻直到 Ctrl-C
npm run engine:headless -- --duration 600 --interval 30    # 跑 10 分钟，30 秒一轮
```

参数：

| 参数 | 说明 |
| --- | --- |
| `--config <dir>` | 数据目录（内含 `config.json` / `seen.json` / `state.json` / `hits/` / `pipeline/` / `reports/` / `logs/` / `feedback.json`），默认 `./data/headless`。首次运行生成默认配置（chmod 600）并提示填写 |
| `--once` | 跑一轮后退出，打印 `fetched / fresh / hits / notified / failed / muted-or-unconfigured` 统计；多来源下 `fetched` / `fresh` 为**全来源聚合求和**（单来源时与旧口径一致），去重键与 engine 同口径 `${来源id}:${帖子id}`。**退出码：仅抓取失败（退避/挑战）为 1**；无就绪推送通道或推送失败均为 0 |
| `--duration <sec>` | 运行指定秒数后优雅退出（默认直到 Ctrl-C / SIGTERM） |
| `--interval <sec>` | 临时覆盖轮询间隔（钳到 ≥15s），**不写回配置**；优先级最高——配置热重载改了盘上的 `pollIntervalSec` 也压不过它（启动参数意图，每次读取配置时重新叠加） |
| `--web [port]` | 起 **Web 管理界面**（Docker 部署的 UI 面；缺省端口 8787，`FW_WEB_PORT` 同效）。托管渲染层构建产物（`FW_WEB_ROOT`，缺省 `./out/renderer`）——与桌面版**同一套界面**（监控台 / 今日回顾 / 设置 / 流水），浏览器打开即用。`--once` 单轮模式不起 |

环境变量：`NSM_BOT_TOKEN` / `NSM_CHAT_ID` 注入 Telegram 凭据——只进内存、不落盘，**覆盖配置里第一个 telegram 通道**的对应字段（对应环境变量非空才覆盖，否则保留盘上值；通道 enabled 不动——用户显式关掉的通道不会被环境变量唤醒）。多 telegram 通道时只覆盖首个。注入是常量叠加层，配置热重载后照常生效。

## Docker 部署

官方镜像 `cashewchickengazgazgood/forumwatch`（amd64 / arm64 双架构）：无头内核 + **与桌面版完全相同的网页管理界面**——渲染层是同一份构建产物，浏览器里由 web-shim（`src/renderer/src/lib/web-shim.ts`）把桌面的 preload IPC 桥到 HTTP（`POST /api/invoke`）+ SSE（`GET /api/events`），UI 代码零改动。

### 快速开始

```bash
docker run -d --name forumwatch \
  -p 8787:8787 -v fw-data:/data \
  -e TZ=Asia/Shanghai \
  -e FW_WEB_TOKEN=换成强口令 \
  cashewchickengazgazgood/forumwatch
```

浏览器打开 `http://<主机>:8787`——首次会提示输入访问令牌（即 `FW_WEB_TOKEN`，存 localStorage，之后不再问）。设置 → 关键词 / 来源 / 推送通道 / AI 与桌面版用法完全一致；网页保存配置后约半秒热重载生效（headless 配置 watch 语义，无需重启容器）。

### 环境变量与端口

| 变量 | 说明 |
| --- | --- |
| `TZ` | 时区（如 `Asia/Shanghai`）。日报 / 命中 / 日志全按本地自然日分桶，**务必设置** |
| `FW_WEB_TOKEN` | 管理界面访问令牌。设置后全部 `/api/*` 需携带（Bearer 头或 `?token=`）；**公网可达时必须设置**——配置面含 Telegram / AI 凭据且可全量改写。纯内网可留空（日志会 warn） |
| `FW_WEB_PORT` | 容器内监听端口（缺省 8787；一般不用改，宿主侧映射换端口即可） |
| `NSM_BOT_TOKEN` / `NSM_CHAT_ID` | 快速注入 Telegram 凭据（只进内存不落盘，优先级高于 config.json，语义同 headless） |

### 数据与升级

数据全部在 `/data` 卷：`config.json / seen.json / state.json / hits/ / pipeline/ / reports/ / logs/ / feedback.json`。升级：

```bash
docker pull cashewchickengazgazgood/forumwatch
docker rm -f forumwatch && docker run -d ...（原参数，建议用 docker compose up -d）
```

升级不丢数据；桌面版凭据密文（`enc:v1:`）在容器里按未配置处理（PlainSecretBox 语义，见故障排查矩阵）——从桌面迁到 Docker 时在网页设置里重填一次凭据即可，或用备份导出 / 导入（网页「数据」卡：导出为浏览器下载的 JSON，导入选文件上传；导入成功后容器会自动暂停监控，**重启容器生效**，`restart: unless-stopped` 下即 `docker restart forumwatch`）。

### 与桌面版的差异

功能面完全一致（监控 / 匹配 / 推送 / AI / 日报 / 遥控 / 流水 / 统计 / 测试台），差异仅三处：

1. **RSS 挑战无 B 计划**：桌面端被 Cloudflare 挑战后可换 Chromium 网络栈重发，容器内没有浏览器内核，被拦即按退避曲线自愈（与桌面 B 计划仍被拦后的行为一致）；
2. **更新检查指向 GitHub Releases**：Docker 升级靠换镜像，「关于」卡看到的"有新版"只是版本信息，不对应容器内自动更新；
3. **看门狗不在**：headless 装配无桌面端 30s 看门狗（桌面专属自愈）。

### 镜像构建与发布（维护者）

- 镜像由 `.github/workflows/docker.yml` 在 **tag `v*` 推送时自动构建并推送**（`latest` + 版本号双 tag；手动 dispatch 可重跑）；凭据在 repo secrets `DOCKERHUB_USERNAME` / `DOCKERHUB_TOKEN`。本机构建走 `npm run docker:build`（tag 0.7.x 从 package.json 读）。
- Dockerfile 两阶段：构建阶段 `npm ci` → 渲染层 vite 构建 → esbuild 把 `scripts/headless.ts` 打成单文件 `server.js`（`--packages=external`，cheerio / undici / fetch-socks 由运行阶段 `npm ci --omit=dev` 提供）；运行阶段 `node:22-alpine` + server.js + web 静态产物，入口 `node server.js --config /data --web 8787`。
- 本地不带 Docker 也能验证服务器：`npm run build && npx esbuild scripts/headless.ts --bundle --platform=node --format=cjs --packages=external --outfile=dist/server.js && node dist/server.js --config /tmp/fw --web 18787`。



AI 能力（语义监控、每日总结、反馈注入）在 headless 下与桌面版同款接线，读同一份 `config.json` 的 `ai` 段——在 headless 数据目录手工编辑配置即可启用（保存后热重载生效，见下）。反馈闭环无 UI 入口但内核同款：语义评估同样读该目录的 `feedback.json` 注入提示词，可手工编辑该文件（启动加载时超限收编到各方向 100 条）；处置流水同样写 `<dir>/pipeline/`。多通道推送装配（channels / notify / routing）同样与桌面版同款：为就绪通道构造发送器并包 CompositeNotifier 做路由扇出，telegram 通道恒走代理、bark/ntfy/webhook 随 proxyScope（`telegram-only` 直连）。

Telegram 遥控（R9）同样与桌面同款接线：常驻模式且 `notify.remoteControl.enabled` 且 telegram 凭据齐备时长轮询启动，指令 / allowlist / 409 / 生命周期语义与桌面完全一致（env 凭据注入对遥控同样生效；`--once` 单轮模式不接——进程即退）。凭据方面 headless **恒明文**（显式注入 PlainSecretBox）：本目录自写自读无感；若把桌面端数据目录指给 headless，桌面写的 `enc:v1:` 密文字段按未配置处理（见故障排查矩阵）。

### 配置热重载（常驻模式，R8 起）

旧文档「headless 配置是启动时快照、改配置需重启」的说法**已作废**。常驻模式下进程监听数据目录，直接编辑 `config.json` 保存后约半秒（500ms 去抖）自动重载，无需重启：

- **监听机制**：盯数据目录而非 config.json 文件（macOS 原子写 tmp+rename 会换 inode，盯文件会丢事件；目录级监听对换 inode 无感）；一次保存触发的事件风暴被去抖合并为一次回调。
- **diff 静默**：回调重读配置与上次盘上值做顶层键 diff，无变化直接返回——`seen.json` / `state.json` 每轮的例行写入会触发目录事件但 diff 为空，**不产生任何重载动作**；有真变化记日志 `config reloaded (key changes: ...)`。
- **多数配置零动作生效**：引擎、来源适配器、发送器、AI provider 全部经访问器每次现读配置——关键词、来源增删 / 启停、通道凭据、路由规则、AI 配置、监控模式、轮询间隔等**下一轮轮询即生效**（轮询间隔在每轮结束重排下一轮时取新值）。
- **两类派生物显式重建**：代理地址 / 作用域变更 → 三个 HTTP client 整体重建（日志 `proxy clients rebuilt`，会中断其上在途请求）；就绪通道集合变化 → 推送扇出重建（日志 `notify fan-out rebuilt`）。
- **例外与边界**：`--interval` 启动参数**始终最高优先**；seen 去重容量在启动时按来源数定死，增删来源需重启才扩容；`--once` 单轮语义不做热重载（也不起监听）；手工编辑时字段须在外层 `config` 对象内、信封 `schemaVersion` 必须为 `4`（写成其他值按损坏处理——备份后回默认，热重载会读到回退后的默认配置）。

headless 添加来源也是改这份文件的 `config.sources`（形状见[配置项参考](#配置项参考)），或直接复制桌面版配置过来用（保存即重载）。

## 故障排查矩阵

| 症状 | 先看什么 | 常见原因与处理 |
| --- | --- | --- |
| 收不到任何通知 | 设置 → 推送通道 → 发送测试消息 | 测试消息向全部就绪通道广播——全部收不到：代理不通（Telegram 通道）/ token 无效 / chatId 错 / 没给 bot 发过消息 / 全部通道未就绪（状态点非绿） |
| 某个通道收不到（其余正常） | 「推送通道」卡就绪状态点 + 命中记录 `notifyDetail` + 日志 | ①通道未启用或凭据未配齐（状态点黄/红）；②代理作用域——`telegram-only` 时 Bark / ntfy / webhook **直连**（端点只在代理网络可达就切 `all`），Telegram 通道反之要走代理；③Bark 业务码非 200（deviceKey 失效，HTTP 200 不代表送达）；④webhook 5s 超时或 secret 不符被消费端拒；⑤路由规则把该类命中分流到了别的通道。`notifyDetail` 逐通道写明成败与错误 |
| 测试消息能收、但没推送 | **「流水」页**（按标题搜该帖看去向；辅助：监控台状态 + 挂起行） | 按去向分四类：①**未命中**——关键词为空或没命中（miss / 语义未中 / 置信度低于阈值，detail 带 score 与阈值）；②**已拦截**——排除词 / 来源分类作者过滤 / 旧帖（id 阈值）/ 置顶 / 相似去重吞并（detail 带原因）；③**挂起中**——免打扰窗内 / 摘要模式（deferred / deferred-skip，到点冲刷补发不是丢了；冲刷后迁移为推送结果）；④**推送结果**——推送失败（detail 带失败原因，下轮自动重试）/ 静音（推送总开关关闭或无就绪通道）。若整段时间无流水记录 → 抓取被 Cloudflare 拦截（等自动恢复）。判定细节仍可用匹配测试台复现；通道侧问题（某通道没收到）看上一行的 `notifyDetail` 路径 |
| 免打扰时段"没推送" | 监控台挂起行 + 推送策略卡 | 窗内命中按设计挂起（不入已读、暂不计数），**窗尾随下一轮轮询冲刷**——不是丢了。核对窗区间：跨午夜（23:00→08:00）合法；**起止相等 = 空区间恒不静默**（想静默请改时刻）；冲刷只随轮询 piggyback，暂停监控期间不冲刷、恢复后首轮补发；重启丢队列但仍在首页的帖子会重新处理（自愈） |
| 摘要模式没到点不推 | 推送策略卡 + 挂起行 | digest 批窗口**从本批第一条挂起起算**，满 `digestIntervalMin`（默认 15 分钟）才冲刷——刚挂起就想收到是等不到的。冲刷是**逐条补发**不是合并成一条汇总。暂停监控期间不冲刷 |
| 路由规则不生效 | 路由规则卡 | ①**首条命中**：排在前面的规则先匹配走了，检查列表顺序（顺序即优先级）；②条件之间 AND——来源 + 方式 + 规则须同时满足，勾多了反而不命中；③when 引用的来源 / 价格规则被删后保存时会**剔除该条件字段**（规则静默变宽，不是报错）；引用的通道被删则整条丢弃；④规则指向的通道未就绪（未启用 / 凭据缺失）时该通道不会发送，且**不会回退广播**（首条命中即定格目标，推送按失败重试）；⑤测试消息与日报不受路由影响是设计行为 |
| Telegram 遥控没反应（发指令无回声） | 设置 → Telegram 遥控卡 + 运行日志 | 按序核对：①开关没开 / Telegram 通道凭据不齐（就绪 = botToken 与 chatId 均非空，缺一监听根本不启动）；②发指令的 Chat ID 不在允许清单——**清单外一律静默忽略，连 /help 也不回**（主 Chat ID 隐含允许；群聊用负数 id，如 `-1001234567890`）；③**409 独占冲突**：启用后本应用独占该 bot 的 getUpdates，同时跑的其他轮询工具 / 另一实例会互相 409（日志 `telegram getUpdates returned 409`，同消息 5 分钟去重 + 60s 自动退避重试；请停掉一边；应用启动时会自动清历史 webhook）；④**暂停中不是没反应**：/pause 后监控停但遥控监听仍在（独立生命周期），此时 /status / /resume 照常应答、/resume 把监控救回来——这是设计行为；⑤只认 `/` 开头的指令文本（群聊可带 `@botname` 后缀），普通聊天文本静默忽略 |
| 状态"Cloudflare 拦截" | 监控台 | 自动退避重试会自愈；频繁出现调大间隔，或代理作用域切 `all` 换出口 |
| 新加的 RSS 源恒显示"Cloudflare 拦截" | 来源状态块（按来源看是哪一个） | linux.do / LowEndTalk 等 RSS 在部分网络被 CF 常态拦截——网络依赖，不是配置错误；桌面端被挑战时已自动换 Chromium 网络栈重发一次（B 计划，见下一行），仍被拦才显示拦截。把代理作用域切 `all` 换出口试试（作用于主抓取请求），或停用该来源。单来源被拦不影响其他来源继续抓取 |
| RSS 源桌面端"Cloudflare 拦截"（B 计划边界） | 日志 `retrying via browser stack`（换栈重发的观测） | 桌面端主抓取被挑战后自动换 Chromium 栈重发一次，仍被拦说明换栈也没过。**边界**：降级请求走**系统代理**、不受应用内代理配置影响（想让降级走代理需设置系统代理，应用内「网络（代理）」只作用于主抓取）；按既有 CF 语义自动退避自愈。headless 模式无此降级（行为与从前一致）；linux.do / LowEndTalk 的降级实际效果未做长期真机验证 |
| V2EX 来源频繁退避 / 日志见 `v2ex rate limit (HTTP 429)` | 状态卡"最近错误" + 日志 | V2EX 未认证 API 限速约 120 次/小时，默认 60s 轮询（60/h）在限内；调小过轮询间隔的话请调大（≥60s），退避曲线会自行恢复 |

| 推送里出现老帖（被回复顶起的旧帖） | 监控台日志 + `state.json` | 已由 id 阈值过滤（`maxSeenTopicId`，按来源分字段）拦截——仅对 id 随创建递增的来源生效（NodeSeek / V2EX；RSS 来源不做该过滤，靠 seen 去重兜底）；若仍出现，检查 `state.json` 该来源的 `maxSeenTopicId` 是否缺失/为 null（如手工清过 state），下一轮成功抓取会自动初始化阈值吞掉整页旧帖，再下一轮起过滤生效 |
| 锐评没出现 | 设置 → 推送锐评 + 监控台 AI 状态块 | ①开关被关（`ai.commentary.enabled`）；②AI Provider 未配置；③该帖生成失败（网络/超时/限流，失败不重打）。锐评缺席不影响推送本身 |
| 价格规则不命中 | 设置 → 匹配测试台 | 测一次看「价格规则」阶段的**提取结果**：裸数字（「年付88」的 88）无币种标记不算价格；半年付 / 季付不识别；多价格标题只取首个；币种 / 周期与规则不符；keywords 前置未命中；规则被停用。识别不了的写法一律不命中（宁缺勿错）——用规则 keywords 缩小范围，而不是指望提取器猜 |
| 重复帖没被相似降噪拦住 | 设置 → 相似降噪 + 运行日志 | 多为**能力边界**而非故障：降噪只拦"装饰级"变体（加标签 / emoji / 全角半角 / 大小写），换词级改写（相似度 ≈0.22）与大幅加词（≈0.67）在 0.72 阈值下拦不住——交给 AI 语义判断或手动调低阈值（代价：可能误杀正常新帖）。另核对：窗口只含近 48h**成功推送**过的标题（更早的、推送失败的、静音的不在窗内）；归一化后不足 6 个字符的短标题不参与判定；日志 `similar topic swallowed` 是被拦下的记录 |

| headless 读桌面端数据目录：凭据全部"未配置"（密文字段读不出） | 运行日志 `[config] 加密凭据解密失败，按未配置处理` + config.json（凭据值为 `enc:v1:` 前缀） | 跨环境互操作边界：桌面端的凭据密文绑定本机 OS 钥匙串（safeStorage），headless 恒明文——PlainSecretBox 对带 marker 的值返回 null，字段按**未配置**处理（置空，不会把 base64 密文当 token 发出去），整次加载只报一条 error。设计行为不是丢数据：同机复用需在 headless 数据目录重填凭据，或从桌面端「数据」卡导出明文备份后手工回填 config.json。反向无碍——headless 写的明文桌面端直接可读，下次保存时自动加密 |
