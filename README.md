# ForumWatch

常驻系统托盘的论坛监控工具（v0.2 起：多论坛架构 + AI 能力，前身 NodeSeek Monitor）：按设定间隔轮询论坛新帖，标题命中关键词（字面匹配）、符合价格规则（结构化匹配）或符合你的兴趣描述（AI 语义匹配）时立即推送到你配置的通知通道（Telegram / Bark / ntfy / Webhook 多通道并发，支持按来源或命中方式路由分流、摘要攒批与免打扰时段）；还可让 AI 为每条命中写一句锐评、每天定点把当天命中总结成日报。内置 NodeSeek 与 V2EX 两类来源，并支持添加任意 RSS 2.0 / Atom 论坛源（设置页提供 Linux.do、LowEndTalk 一键预设）。macOS / Windows 双平台。

## 从 NodeSeek Monitor 更名与数据迁移

本应用原名 **NodeSeek Monitor**，现已更名为 **ForumWatch**。

- **老用户升级**：新版首次启动会自动把旧版的配置（关键词 / Telegram / 代理，v0.2 起含 AI 配置）、已读去重记录与运行状态迁移到新的数据目录；旧目录保留不动，随时可以回退装回旧版。
- **Windows 用户务必先退出旧版**（托盘菜单 → 退出）再安装新版：新版与旧版是两个独立应用，同时运行会对同一批帖子**重复推送**。

## 功能特性

- **多论坛来源**：配置以"来源列表"组织——内置 NodeSeek（SSR 页面抓取）与 V2EX（官方 API），外加任意 RSS 2.0 / Atom 论坛源（自定义地址，设置页有 Linux.do / LowEndTalk 一键预设）；每个来源独立健康状态与失败退避，启停 / 增删在「设置 → 来源」完成，保存即生效。
- **关键词监控（字面匹配）**：包含词任一命中即推送，排除词一票否决，大小写不敏感。
- **价格规则（结构化匹配）**：从帖子标题提取周期 / 价格 / 流量（如「年付 ¥99」「500G 流量」），按你定的条件（如"年付 + ≤¥100 + ≥500G"）确定性命中——第三种命中方式，优先于关键词、不受监控模式影响、零 AI 成本（详见「价格规则」一节）。
- **AI 语义监控（可选）**：配置任意 OpenAI 兼容模型（内置 DeepSeek / Kimi / GLM 一键预设），用自然语言描述兴趣，由 AI 判断新帖是否相关；能捕捉"换种说法"的帖子。AI 未配置或当日配额耗尽时自动降级为字面匹配，监控不中断。
- **语义置信度阈值（可选）**：语义命中还可以要求 AI 自报的置信度 ≥ 阈值才推送（默认 0 = 不过滤），进一步压误报；字面与价格规则命中不受影响。
- **相似降噪**：命中推送前与近 48 小时已推送的标题比对相似度，"装饰级"转发变体（加标签 / emoji / 全角半角 / 大小写）不再重复推送；默认开启，阈值可调。
- **匹配测试台**：设置页粘贴一条标题，按已保存配置逐阶段跑判定管线（来源过滤 → 排除词 → 价格规则 → 字面 → 相似 → 语义），看它会命中在哪一步、被什么拦下；只读诊断，可选择真调一次 AI（不占用每日 300 次额度）。
- **AI 锐评（可选）**：命中推送时让 AI 给帖子附一句一句话锐评（消息里的 💬 行），默认开启、设置页可关；独立于匹配模式，字面命中也能有锐评。
- **AI 每日总结（可选）**：每天定点把当天命中总结成 markdown 日报，推送到全部就绪的推送通道（超长自动分段），并可在应用内「今日回顾」页翻看近 14 天；零命中也会生成"今日无命中"心跳。
- **多通道推送**：推送通道不限于 Telegram——支持配置多条通道并按需组合：**Telegram Bot**（HTML 消息含标题、分类、作者、命中的关键词与原帖链接）、**Bark**（iOS，deviceKey + 可选自建服务器，默认官方 api.day.app）、**ntfy**（topic + 可选自建服务器，默认官方 ntfy.sh）、**Webhook**（把命中打包成结构化 JSON POST 到你指定的地址，可带 `X-ForumWatch-Secret` 鉴权头，供自建自动化/归档消费）。任一通道投递成功即算推送成功；每条命中记录里带 per-channel 送达明细。旧版只配过 Telegram 的用户升级后自动迁移，无需任何操作。
- **推送策略**：「设置 → 推送策略」可选**实时推送**（默认，命中即推）或**摘要攒批**（命中先挂起，每 1-120 分钟（默认 15）到点把挂起的命中**逐条**补发）；另有**免打扰时段**（如 23:00-08:00，支持跨午夜，窗内命中的推送挂起到窗尾合并补发）。挂起的帖子不入已读、不产生命中记录，到点补发；挂起条数实时显示在监控台。
- **路由规则**：「设置 → 路由规则」按条件把命中分流到指定通道（如"NodeSeek 来源的规则命中只推 Telegram、语义命中推 ntfy"）；条件可组合来源 / 命中方式（字面/语义/规则）/ 具体价格规则，按列表顺序首条命中生效；无规则命中时推给全部就绪通道。测试消息与日报不受路由影响（恒广播全部通道）。
- **常驻托盘**：关闭窗口即最小化到系统托盘继续监控，退出请走托盘菜单。
- **稳健轮询**：默认 60 秒一轮（最低 15 秒，带 ±20% 随机抖动防反爬）；连续失败自动指数退避，封顶 30 分钟，恢复成功后自动复位。
- **Cloudflare 感知**：被 Cloudflare 挑战拦截时状态栏显示"Cloudflare 拦截"并自动退避重试，不误报数据。
- **代理支持**：`http(s)://` 与 `socks5://`，作用域可选"仅 Telegram 走代理"（Telegram 通道走代理，站点抓取、AI、Bark/ntfy/Webhook 直连）或"全部请求走代理"。
- **首启防打扰**：首次启动只把当前帖子记为已读、不推送，避免安装瞬间收到一大堆历史通知。
- **推送限流与重试**：遵守 Telegram 官方限速（约 1 条/秒，1050ms 队列间隔），遇 429 自动等待服务端指示的时间后重试；Bark / ntfy / Webhook 通道为 200ms 温和防抖（webhook 单次请求 5 秒超时）。所有通道发送失败自动重试 3 次（间隔 1s / 2s）。
- **数据全部本地**：配置、已读记录、命中记录、日志存在本机 userData 目录，不上传任何数据（AI 功能仅在你主动配置后，把帖子标题/分类与兴趣描述发往你自己填写的模型服务地址）。

应用没有做代码签名和公证，首次打开会被 Gatekeeper 拦截，这是预期现象：

1. 下载 `.dmg`，把 **ForumWatch** 拖入「应用程序」文件夹。
2. 在「应用程序」里找到它，**右键点击 → 打开 → 再点"打开"**（不要直接双击）。
   只需要做一次，之后可正常双击打开。
3. 如果仍提示"已损坏"，可在「终端」执行（把路径换成实际安装位置）后，再右键打开：

   ```bash
   xattr -cr /Applications/ForumWatch.app
   ```

安装包未签名，运行时 SmartScreen 会弹蓝色警告，这是预期现象：

1. 双击安装包，出现 SmartScreen 提示时点 **"更多信息"**。
2. 再点 **"仍要运行"**，按提示完成安装。

## 快速上手

7 步跑起来（第 3、6 步可选）：

1. **安装并启动**应用（见上一节）。首次启动会把首页现有帖子记为已读，不会推送。
2. **填写关键词**：左侧栏进入「设置 → 关键词」，在"包含关键词"里加入你关心的词（如 `VPS`、`白嫖`），回车确认；可选填"排除关键词"。填完点「保存设置」。
3. **（可选）添加更多来源**：默认只监控 NodeSeek。「设置 → 来源」可一键添加 V2EX、Linux.do、LowEndTalk 预设，或填入任意论坛的 RSS 2.0 / Atom 地址（如 `https://example.com/latest.rss`）；每个来源可单独启停。注意 Linux.do / LowEndTalk 的 RSS 在部分网络会被 Cloudflare 拦截（届时显示"Cloudflare 拦截"并自动退避，可配合代理，见「网络与代理」）。
4. **创建 Telegram Bot**（主推路径；也可跳过本步用 Bark / ntfy / Webhook，见下）：
   1. 在 Telegram 里找 [@BotFather](https://t.me/BotFather)，发送 `/newbot`，按提示起名，得到 **Bot Token**（形如 `123456789:ABCdefGHI...`）。
   2. **给你刚创建的 bot 发一条消息**（任意内容，比如 `hi`）。不先发消息，bot 无法主动给你推送。
   3. 获取 **Chat ID**，两种方法任选：
      - 方法一：给 [@userinfobot](https://t.me/userinfobot) 发任意消息，它回复里的 `Id` 就是你的 Chat ID。个人聊天是正数；群组是负数（通常是 `-100` 开头），需先把 bot 拉进群并在群里发条消息。
      - 方法二：浏览器打开 `https://api.telegram.org/bot<你的Token>/getUpdates`（把 `<你的Token>` 换成第 1 步的 token），返回 JSON 里 `message.chat.id` 字段就是 Chat ID。
5. **配置推送通道**：「设置 → 推送通道」里展开默认的 Telegram 通道，填入 Bot Token 与 Chat ID，点「保存设置」。旧版只配过 Telegram 的用户升级后凭据自动迁移到该通道，无需重填。也可以点「添加通道」再加别的：
   - **Bark**（iOS 推送）：填 App「首页→复制」得到的 Device Key，可选自建服务器地址（留空用官方 `api.day.app`）。
   - **ntfy**：填订阅的 Topic，可选自建服务器地址（留空用官方 `ntfy.sh`）。
   - **Webhook**：填接收地址，命中会以结构化 JSON POST 过去（可选 Secret 鉴权头），供自建自动化/归档消费。
   每条通道独立启停；同一命中会推给全部就绪通道（或在「路由规则」里按条件分流）。可选在「推送策略」里切换摘要攒批 / 免打扰时段。
6. **（可选）配置 AI**：「设置 → AI 模型」里选一个预设（DeepSeek / Kimi / GLM）或手动填任意 OpenAI 兼容服务的 Base URL / API Key / 模型名，点「测试连接」验证，保存后即可在「设置 → 监控模式」切换到语义匹配、在「每日总结」开启 AI 日报。不配 AI 也能正常用，应用按字面关键词监控（详见「AI 功能」一节）。
7. **点「✈ 发送测试消息」**：会向**全部就绪通道**各发一条测试消息（Telegram 里收到 `✅ ForumWatch 测试消息` 即配置成功；Bark / ntfy / Webhook 同理，消息里带通道名）。之后保持应用运行（窗口可以关，托盘常驻），新帖命中关键词（或被 AI 判定相关）就会推送。

> 大陆用户请先阅读下面的「网络与代理」一节，api.telegram.org 通常需要代理才能访问。

## 关键词语义

关键词决定"哪些帖子值得推送"，规则如下（只匹配**标题**，不匹配正文）：

- **包含关键词**：多个词之间是"或"的关系——标题命中任意一个即触发推送。
- **排除关键词**：一票否决——标题命中任意一个排除词，即使同时命中包含词也不推送。
- **大小写不敏感**：`VPS` 与 `vps` 等价（对中文无影响）。
- **匹配方式是子串**：关键词 `nginx` 能命中标题 `宝塔nginx反代教程`，也会命中 `tengine-nginx对比`。
- **⚠️ 包含关键词为空 = 不推送任何帖子**。这是故意的防误设计：没配关键词时不推送，避免全量帖子刷屏。刚装好收不到通知，先检查这里。

示例：

| 包含词 | 排除词 | 标题 | 结果 |
| --- | --- | --- | --- |
| `VPS, 白嫖` | `广告` | `免费白嫖一年的 VPS` | 推送（命中"白嫖""VPS"） |
| `VPS, 白嫖` | `广告` | `VPS 广告位招商` | 不推送（命中排除词"广告"） |
| `VPS, 白嫖` | | `服务器流量计费讨论` | 不推送（未命中包含词） |
| （空） | | 任何标题 | 不推送 |

## 价格规则（结构化匹配）

关键词与 AI 之外还有第三种命中方式：**价格规则**从帖子标题里提取结构化交易信息（周期、价格、流量），与你配置的条件做确定性比对。「设置 → 价格规则」配置，一条规则内的条件之间是 **AND**（全部满足才命中）。规则命中**优先于关键词**（同一帖只记一种命中方式），且**不受监控模式影响**——纯语义模式下同样生效，零 AI 成本。

提取口径总原则「宁缺勿错」：识别不了的写法不产出字段、规则不命中，而不是猜一个近似值去比较。

| 字段 | 认这些写法 | 不认这些 |
| --- | --- | --- |
| 周期 | `年付` `每年` `包年` `3年` `1,299元/年` `annual` `per year` `yearly`；`月付` `每月` `15元/月` `monthly` `per month`、独立词 `mo` | 半年付 / 季付 / 双月付（不识别） |
| 价格 | `¥99` `￥99` `99元` `99 块`（人民币）；`$9.9` `9.9刀` `USD 20`（美元） | **裸数字**（如「年付88」的 88，无币种标记不算价格）；多价格标题只取首个 |
| 流量 | `500G/GB`、`0.5T/TB`、`1024M/MB`（自动换算成 GB 再比较） | `2C2G` 里的 2G（那是内存）、`500Mbps`（那是带宽）；「不限流量」视为无约束 |

示例（规则：周期 = 年付、价格上限 ¥100、流量下限 500G）：

| 标题 | 提取结果 | 判定 |
| --- | --- | --- |
| `年付 ¥99 的 VPS，500G 流量` | 年付 · ¥99 · 500G | 命中 |
| `[分享] 年付 ￥99 的 VPS 500G！！` | 同上（装饰符不影响提取） | 命中 |
| `月付 $9.9 512M 小鸡` | 月付 · $9.9 · 0.5G | 不命中（周期 / 价格 / 流量均不满足） |
| `年付88 拿下` | 年付（无价格） | 不命中（88 是裸数字，提取不到价格） |

补充规则：

- 每条规则可配 **keywords 前置**（AND 条件）：非空时标题须包含任一关键词，规则才参与判定——用于缩小范围（如多价格对比帖）。
- 一条规则**所有条件都留空（不限）= 全匹配**（每帖都命中）——是否这样用由你自己负责。
- 上限 20 条规则，每条规则 keywords ≤ 20 个。
- 规则总不命中？把标题丢进「设置 → 匹配测试台」，价格规则阶段会显示从标题实际提取出的周期 / 价格 / 流量。

## AI 功能（语义监控与锐评）

字面关键词只能匹配"字面出现"的词。语义监控把判断交给大语言模型：你用自然语言描述兴趣，AI 逐帖判断是否相关，能捕捉同义与换说法的表达（想关注"白嫖羊毛"，标题写"零成本薅一年"也能命中）。

### 配置 Provider

「设置 → AI 模型」卡片，三个字段：**Base URL / API Key / 模型名**。任何 OpenAI 兼容的 chat/completions 服务都能用，内置三个一键填充的预设：

| 预设 | Base URL | 模型 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| Kimi | `https://api.moonshot.cn/v1` | `kimi-k2-0711-preview` |
| GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4.7` |

点预设只填地址和模型名，**API Key 要自己填**（在各服务的开放平台申请）。填完点「测试连接」——按已保存的配置发一条最小对话，验证地址 / Key / 模型可用（表单有未保存改动时会提示先保存再测试）。

### 选择监控模式

「设置 → 监控模式」三选一：

- **字面匹配**（默认）：只用关键词，不调 AI，零成本。
- **语义匹配**：只用 AI 按兴趣描述判断（**兴趣为空时语义档永不命中**，与字面档"关键词为空不推送"同一条防风暴规则）。
- **字面 + 语义（任一命中）**：先字面后 AI，字面命中的帖子不再送 AI（省调用），未命中的再由 AI 判断；任一命中即推送。

### 写兴趣描述

兴趣是标签输入（回车添加），每条一句自然语言，最多 20 条。写法要点：**说清楚"你要什么"，而不是罗列关键词**——关键词是字面档的事，兴趣描述给 AI 看场景和意图。示例：

- `Oracle 免费 ARM 的羊毛`——比关键词 `ARM` 精准得多，能框住"OCI 白嫖服务器"这类说法
- `各大云厂商的低价新用户活动，年付 100 元以内的小鸡`——价格区间、对象、用途都交代了
- `K8s / 虚拟化相关的折腾教程，排除纯广告`

### AI 锐评（命中推送附加点评）

开启后，每条命中推送的消息里会多一行 `💬 锐评: …`——AI 对帖子标题写的一句简短点评（60 字以内），纯锦上添花。

- **开关位置**：「设置 → AI 模型 → 推送锐评」，默认**开启**；关闭后推送恢复纯净格式（标题 / 分类 / 命中词 / 链接）。
- **成本与限额**：每次命中额外调用一次 LLM；每日子限额 **100 次**，并与语义评估共享每日 **300 次**总额度（锐评一次同时计入两者，监控台 AI 状态块分别显示 `今日调用 N/300` 与 `锐评 N/100`）。子限额用完当日静默降级为无锐评推送，次日恢复。
- **独立于匹配模式**：锐评不依赖语义监控——字面匹配命中的帖子同样会有锐评，只要配置了 AI 模型且开关打开；反过来关闭锐评也不影响语义匹配。生成失败（网络 / 超时 / 限流）只导致该条推送没有锐评，绝不影响推送本身。

### 行为细节与限额

- **排除词仍然一票否决**：语义模式下，标题命中任一排除词直接跳过，不送 AI。
- **每帖只评一次**：一条帖子 AI 给出"不相关"结论后不再重评；评估未决（如超时、响应异常）的帖子不记为已读，下一轮自然重评，滚出首页即止。
- **每日评估上限 300 次**（调用按本地自然日滚动计数）。耗尽后自动降级为字面匹配，次日恢复；监控台 AI 状态块会显示 `今日 N/300` 与降级原因。
- **AI 失败不影响监控**：AI 报错（网络 / 鉴权 / 限流）只记入"最近错误"并沿用降级逻辑，不进轮询失败计数，帖子抓取与字面匹配照常。
- **数据流向**：AI 请求只包含帖子标题、分类与你的兴趣描述，只发往你配置的 Base URL；API Key 仅存本机 `config.json`（600 权限），日志与错误消息全脱敏。

## 每日总结（AI 日报）

「设置 → 每日总结」开关 + 时刻（默认 22:00，本地时区）。开启后每到设定时刻，把**当天命中**（落盘在 `hits/` 的记录）交给 LLM 总结成 markdown 日报：

- **推送**：复用同一推送链路，推送到全部就绪通道（不走路由规则），超长自动按行分段（尾缀"（续 N）"）；推送失败只记日志，不影响日报落盘。
- **应用内查看**：「今日回顾」页可翻最近 14 天的日报。
- **零命中心跳**：当天没有任何命中也会生成"今日无命中"的固定文案日报并推送（不调 LLM），确认监控活着。
- **不回溯、不补做**：应用在设定时刻关机/未运行，错过的日期不补；暂停监控期间不生成。应用启动/唤醒时会检查"今天到了时刻但还没生成"，只补当天。
- **手动生成**：「今日回顾」页点「立即生成」随时出当天的日报；当天已有日报时重新生成会**覆盖**旧文件。
- **降级兜底**：LLM 总结失败时自动降级为机械拼接模板（标题列表式日报），日报不断档。

## 网络与代理（大陆用户必读）

应用的外网请求分三类：抓取各论坛来源（NodeSeek、V2EX、你添加的 RSS 源——NodeSeek 大陆一般可直连，Linux.do / LowEndTalk 等部分 RSS 源在部分网络会被 Cloudflare 拦截）、推送（Telegram 通道走 `api.telegram.org`，大陆通常需要代理；Bark / ntfy / Webhook 走你配置的端点——官方网关 `api.day.app` / `ntfy.sh` 或自建服务器，通常直连可达）、以及 AI 请求（仅配置后，走你填写的 Base URL）。

在「设置 → 网络（代理）」配置：

- **代理地址**：支持 `http://`、`https://`、`socks5://` 三种前缀，如 `socks5://127.0.0.1:1080` 或 `http://127.0.0.1:7890`。留空表示直连。地址必须以这三个前缀之一开头，否则保存时会被清空。
- **作用域**（二选一）：
  - **仅 Telegram 走代理（默认）**：论坛抓取、AI 请求、Bark / ntfy / Webhook 通道直连，只有 Telegram 通道走代理。大陆用户的推荐配置（Bark / ntfy / Webhook 的自建端点多在本机或内网，直连正确）。
  - **全部请求走代理**：论坛抓取、AI 请求与全部推送通道（含 Bark / ntfy / Webhook）都走代理。适合论坛源、AI 服务或自建推送端点也需要代理访问的网络环境。

配置修改后保存即生效，无需重启。

## 常见问题

### 没收到通知，怎么排查？

按顺序检查：

1. **测试消息能收到吗**：监控台或「设置 → 推送通道」点「发送测试消息」——它会向**全部就绪通道**各发一条，哪个通道没收到就是哪个通道的问题。
   - 某个通道收不到 → 是该通道配置/网络问题：看「推送通道」卡的就绪状态点（凭据是否配齐、通道是否启用）、代理作用域（Telegram 通道在"仅 Telegram 走代理"时走代理，其余通道直连——自建端点在代理网络里不可达时切"全部走代理"或反之）。命中记录与日志里有 per-channel 送达明细（`notifyDetail`），能看到具体哪个通道失败、为什么。
   - 全都收不到 → 是关键词/帖子问题，继续第 4、5 步。
2. **代理设置对不对**（Telegram 通道）：大陆访问 api.telegram.org 必须配代理。确认代理地址正确且代理进程在运行；如果代理挂了，换成可用节点再点测试。
3. **Chat ID 对不对**（Telegram 通道）：确认拿到的是你自己的 Chat ID，且你已经给 bot 发过至少一条消息（bot 无法主动发起会话）。
4. **关键词配了吗**：包含关键词为空 = 不推送（见上一节）。确认关键词拼写、以及帖子标题确实包含它。
5. **被 Cloudflare 拦截了吗**：状态卡显示"Cloudflare 拦截"时抓取暂停，恢复前不会有新命中，见下一问。
6. **开了免打扰或摘要模式吗**：监控台状态卡下有「⏳ 挂起待推送 N 条」就是——命中被挂起了，免打扰窗尾 / 摘要到点会补发（不是丢了）。
7. **看日志**：监控台「运行日志」或配置目录 `logs/log-YYYY-MM-DD.txt`，推送失败会写明原因（网络错误、429、token 无效等）。

### 状态显示"Cloudflare 拦截"怎么办？

部分来源（NodeSeek 部分接口，以及 Linux.do / LowEndTalk 等 RSS 源）在 Cloudflare 后面，会对本应用发起人机验证挑战。此时：

- **先看是哪个来源**：监控台「来源状态块」按来源显示健康状态——单来源被拦不影响其他来源继续抓取。
- **通常什么都不用做**：应用会自动退避重试（间隔逐步放大到最长 30 分钟），一般会自行恢复。
- **想快点恢复**：点「立即轮询」主动补一轮；若立刻再次被拦，说明风控仍在，建议把轮询间隔调大（如 120 秒以上）。
- **某个 RSS 源一直被拦**：部分网络环境对 Linux.do / LowEndTalk 的 RSS 常态拦截（网络依赖，不是你配置错了）——可在「设置 → 网络」把作用域切为"全部请求走代理"换一个出口 IP 试试，或停用该来源。
- **频繁被拦**：多为轮询过快所致，请调大间隔。

### 为什么刚安装/刚启动时没有推送？

首次启动（以及 seen 记录被清空后的启动）会做一次**基线**：把首页当前所有帖子标记为已见、不推送，防止安装瞬间被几十条历史帖刷屏。从基线之后新出现的帖子才参与关键词匹配和推送。每次重启应用不会有这个问题——已读记录持久化在本地。

### 置顶帖为什么收不到推送？

首页置顶帖是运营固定在那里的旧帖（仅 NodeSeek 有置顶帖，RSS / V2EX 来源无此概念），应用会跳过置顶帖的推送（只记为已见），避免同一条公告反复推送。

### 关掉窗口后应用还在运行吗？

在。关窗是最小化到系统托盘，监控继续。托盘图标菜单提供：显示主窗口 / 暂停或恢复监控 / 立即轮询 / 发送测试通知 / 打开配置目录 / 退出。**真正退出请走托盘菜单的「退出」。**

macOS 上应用不出现在程序坞和 Cmd+Tab 切换器里（dock 已隐藏，托盘应用的预期行为），通过菜单栏右侧的托盘图标交互。

### 开机自启开了没生效？

macOS 上未签名应用可能被系统拒绝登录自启（可在 系统设置 → 登录项 中检查）。Windows 打包签名后此问题自然消失，当前版本如遇拒绝请手动启动。

## 隐私说明

- 所有配置（关键词、代理、各推送通道凭据、AI 凭据）、已读记录、命中记录与日志**只存储在本机** userData 目录下的 `config.json` / `seen.json` / `state.json` / `hits/` / `reports/` / `logs/`。
- 应用没有任何统计、埋点或云端服务，**不上传任何数据**。
- 网络请求目标：你配置的各监控来源（`www.nodeseek.com` 抓取首页、`www.v2ex.com` 官方 API、以及你添加的各 RSS 源的 feed 地址）、你配置的各推送通道端点（Telegram 通道 `api.telegram.org`；Bark 通道 `api.day.app` 或你的自建 Bark 服务器；ntfy 通道 `ntfy.sh` 或你的自建 ntfy 服务器；Webhook 通道你填写的接收地址——命中帖子会以 JSON 全文 POST 过去），以及——仅当你配置了 AI——**你自己填写的 AI Base URL**。
- **AI 数据流向**：语义评估与日报总结发给 LLM 服务的只有帖子标题、分类和你的兴趣描述（日报还会带上当天命中列表）；帖子正文、你的其他数据不发。请求只发往你配置的 Base URL。
- `config.json` 含 Bot Token、各通道凭据与 AI API Key，文件权限为 600；请勿把该文件分享给他人。Telegram Token 泄露请到 @BotFather 用 `/revoke` 重置；Bark / ntfy / Webhook 凭据泄露请到对应服务重新生成 / 换 topic / 换 secret；AI Key 泄露请到对应服务商后台作废。日志与错误消息中的凭据一律脱敏显示。

### headless 模式（不经 Electron 直跑内核）

```bash
# 单轮冒烟：抓一轮即退出，打印统计（抓取失败时退出码 1）
npm run engine:headless -- --once

# 指定数据目录（首次运行会生成默认 config.json，chmod 600）
npm run engine:headless -- --config /tmp/nsm-smoke --once

# 常驻运行直到 Ctrl-C
npm run engine:headless -- --config ./data/headless

# 跑 10 分钟、30 秒一轮
npm run engine:headless -- --duration 600 --interval 30

# 用环境变量注入 Telegram 凭据（只进内存，不落盘；覆盖配置里第一个 Telegram 通道）
NSM_BOT_TOKEN=xxx NSM_CHAT_ID=yyy npm run engine:headless -- --once
```

参数：`--config <dir>` 数据目录（默认 `./data/headless`，内含 `config.json` / `seen.json` / `state.json` / `hits/` / `reports/` / `logs/`）；`--once` 跑一轮退出；`--duration <sec>` 运行指定秒数后优雅退出；`--interval <sec>` 临时覆盖轮询间隔（最低 15 秒，不写回配置）。AI 能力在 headless 下同样可用（读该目录 config.json 的 `ai` 段）。

注意：headless 的配置是启动时快照，改配置文件需重启进程（桌面版无此限制，改配置即时生效）。

## 已知限制

- **应用未签名未公证**：macOS 首次打开需右键 → 打开；Windows 会遇 SmartScreen"仍要运行"；mac 上登录自启可能被系统拒绝。
- **数据源多为非官方 / 公共接口**：NodeSeek 来自首页的 SSR HTML（非官方 API）；V2EX 用官方公共 API（未认证限速约 120 次/小时）；RSS 源依赖站点自身的 feed 服务。站点改版、风控策略变化（如 Cloudflare 挑战常态化）或 API 政策变化可能导致对应来源监控失效，需要发版适配；这是长期存在的风险。
- **linux.do / LowEndTalk 预设源有网络依赖**：两者的 RSS 在部分网络会被 Cloudflare 拦截（应用显示"Cloudflare 拦截"并自动退避，不误报数据）；能否稳定抓取取决于网络环境，可把代理作用域切为"全部请求走代理"换出口。
- **只监控各来源第 1 页**：默认每轮只抓第 1 页（NodeSeek 约 49 条最新帖、V2EX 约 40 帖、RSS 为 feed 当前输出的条目）。引擎内置"上一轮整页都是新帖时下一轮补抓第 2 页"的自适应能力，但 2026-09-19 复测：NodeSeek 的第 2 页请求会被服务端忽略页码（返回第 1 页）或直接 403，**当前实际无效**（无害——同页内容自动去重等于无操作）；RSS / V2EX 不支持翻页。极高峰时段两轮间隔内的帖子可能被顶出第 1 页而漏掉。
- **关键词只匹配标题**，不匹配正文、作者、分类（AI 语义评估同样只看标题与分类；价格规则同样只看标题）。
- **相似降噪只拦"装饰级"变体**：标题归一化后按 3-gram Jaccard 比对，加标签 / emoji / 全角半角 / 大小写这类转发变体会被抑制；**换词改写或大幅增删内容的重复帖相似度不够，拦不住**（那类重复交给 AI 语义判断，或手动调低阈值——代价是可能误杀正常新帖）。比对范围仅限近 48 小时成功推送过的标题；归一化后不足 6 个字符的短标题不参与判定。
- **价格规则提取不到裸数字价格**：「年付88」的 88 没有币种标记不算价格；半年付 / 季付不识别；多价格标题只取首个。配规则前建议先用「匹配测试台」验证目标标题的实际提取结果。
- **id 阈值过滤假设帖子 id 随创建递增**（NodeSeek 与 V2EX；RSS 来源不做该过滤）：旧帖过滤依赖"数值 id ≤ 已见阈值 = 旧帖"这一假设。若站点 id 分配出现乱序，偶发的新帖会被误当旧帖跳过（漏报换不误报）；监控台运行日志出现 `page max topic id decreased` 警告即为该假设异常的信号。
- **全局轮询间隔受最差来源影响**：调度器按"配置间隔与各来源剩余退避时间的最大值"排下一轮，单个来源持续退避会拉长所有来源的实际轮询周期。
- **配置格式单向升级（当前 v3）**：新版会自动把 v1 / v2 旧配置迁移到 v3；但旧版应用读到 v3 配置文件会当作损坏配置（自动备份后回默认）——回退旧版本会丢配置，如需长期回退请先在旧版可用时期保留备份。
- **语义监控与日报依赖第三方 LLM 服务**：开启即有相关数据出本机（见隐私说明），且受服务商可用性与你的账户余额/限流约束；关闭后即为纯本地字面监控。语义置信度阈值依赖模型在裁决里返回 `score`——不返回的旧模型按 1.0（完全置信）兼容，此时阈值实际不起作用（DeepSeek / Kimi / GLM 等支持 JSON 输出的主流模型均返回）。
- **日报不回溯**：设定时刻应用未运行则该日无日报（只有当天内会补）；更早的历史命中仍保留在 `hits/` 数据文件中。
- **挂起队列重启丢失（自愈）**：免打扰 / 摘要模式下挂起的命中只存在内存里，重启应用会丢队列——仍在帖子列表第 1 页的挂起帖会被重新匹配（免打扰窗内重新入队、窗外直接推送），不丢推也不双发；但已滚出第 1 页的挂起帖重启后自然消失。
- **摘要模式是"到点逐条发"，不是合并成一条消息**：摘要到点后每条命中仍独立成一条推送（Telegram 一条一条收，webhook 一次一次 POST），只是攒批到点才发；想要真正的"一条汇总消息"目前没有。
- **没有逐通道单独测试按钮**：「发送测试消息」恒向全部就绪通道广播（不走路由）。想单测某个通道，临时停用其他通道再点测试。
- **无自动更新**：升级请手动下载新版安装包覆盖安装。
